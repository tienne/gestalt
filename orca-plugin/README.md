# Gestalt Conductor (Orca 플러그인)

Gestalt 컨덕터가 굴리는 주문과 사람 확인을 기다리는 게이트를 오르카 사이드바와 상태 표시줄, 에디터 탭 보드에 보여 준다. 게이트 승인과 거절도 여기서 한다.

## 하는 일

- 워커가 `gestalt conductor status --all --json --with-activity`를 불러 읽는다. 이벤트 로그를 직접 재생하지 않으니 저장소 꼴이 바뀌어도 CLI만 맞으면 된다. `--with-activity`를 모르는 옛 CLI면 플래그 없이 다시 부르고 워커가 다시 뜰 때까지 그대로 부른다. 그때는 작업 내용 없이 전과 같은 화면이 나온다.
- 워커 작업 내용(지금 고치는 파일, 고친 파일, todo, 서브에이전트, 최근 tool 호출)은 워커 트랜스크립트가 바뀌어도 `events.jsonl`이 안 바뀌어서 감시로는 못 잡는다. 작업 내용이 실린 실행 중 주문이 있으면 10초마다 다시 읽는다.
- 저장소의 `events.jsonl`을 지켜보다 바뀌면 다시 읽는다. 파일이 없으면 5초마다 생겼는지 보고 그동안 "컨덕터 저장소 없음"을 띄운다.
- 상태 표시줄에 `주문 N · 확인 대기 M`을 띄운다. 확인 대기가 있으면 warning, 저장소가 없거나 CLI가 실패하면 danger이고 이유는 툴팁에 있다. 누르면 다시 읽는다.
- 새 게이트가 열리면 데스크톱 알림을 한 번 띄운다. 알린 게이트 id는 플러그인 저장소에 남겨서 워커가 다시 떠도 또 알리지 않는다.
- 패널은 레포마다 타일 하나를 그린 지도로 시작한다. 타일에는 확인 대기 게이트 수와 상태별 주문 수가 붙고 사람 손이 필요한 레포가 앞에 온다. 타일을 누르면 그 레포의 게이트와 상태별 주문, bypass 사후 보고가 나온다.
- 주문을 맡은 워커의 오르카 워크트리를 찾으면 그 주문을 눌러 워크트리로 바로 이동한다. 패널은 주문 제목이나 위계 트리 항목을 누르면 되고 보드는 노드를 두 번 누르거나 옆의 ↗ 버튼을 누른다. 워크트리에서 워커 에이전트가 도는 터미널을 찾으면 그 칸으로 바로 간다. 오르카 호스트 API 1.7 이상에서만 되고 그보다 옛 오르카거나 터미널을 못 찾으면 워크트리만 연다. 그때는 사이드바에서 워크트리를 누른 것과 같아서 마지막으로 보던 탭이 다시 뜬다.
- 레포 이름 옆에 오르카 프로젝트 이름을 붙인다. 컨덕터는 레포를 `owner/name`으로만 알아서 오르카 `workspace.list`의 `project`로 찾는다. 주문을 맡은 워크트리가 있으면 그 프로젝트를 쓰고 없으면 디렉토리 이름이 레포 이름과 같은 워크스페이스를 본다. 후보가 갈리거나 레포 이름과 같으면 붙이지 않는다. 패널과 보드, 폰 페이지가 다 같다.
- 같은 레포 안에서 하위 주문(`parentOrderId`)이나 부모 워크트리(`parentWorktree`)로 이어진 주문이 있으면 타일에 `하위 N`이 붙고 레포 상세에 위계 트리가 나온다. 하위 주문은 상위 주문 밑에 둔다. 부모 워크트리는 그 워크트리를 맡은 주문이 있으면 그 주문 밑에, 없으면 워크트리 이름과 브랜치를 단 노드 밑에 둔다. 컨덕터가 남긴 관계만 그리고 의존성을 따로 추측하지 않는다.
- 탭 바의 + 메뉴에서 "컨덕터 보드"를 고르면 `.conductor-board` 파일을 여는 넓은 보드가 뜬다. 레포마다 카드 하나에 위계 트리를 그리고 오른쪽에 고른 주문의 상세와 게이트가 나온다. 아무것도 안 골랐으면 열린 게이트 전부가 나온다. 파일 내용은 쓰지도 읽지도 않으니 빈 파일이면 된다.
- 탭 바의 + 메뉴에서 "컨덕터 터미널"을 고르면 `.conductor-terminal` 파일을 여는 터미널 꼴 화면이 뜬다. 끝나지 않은 주문마다 카드 하나를 그리고 테두리 색으로 워커 종류를 가른다. 카드에는 스킬 체인 칩과 지금 스킬의 단계와 라운드, todo 막대와 개수, `✎ 지금 파일 · 경과`, 실행 중인 서브에이전트 수, 실행 중이나 대기 사유, rate-limit, 게이트 대기 같은 상태줄, 다음 할 일과 bypass, 하위 주문이 나온다. 왼쪽 컨덕터 칸과 아래 이벤트 로그는 status JSON의 `conductor`와 `recentEvents`만 그리고 화면에서 따로 세지 않는다. 이 필드를 안 싣는 옛 CLI면 그 칸이 빠진다. 주문은 있는데 두 필드가 다 없으면 CLI를 올리라는 안내가 뜬다. 카드를 두 번 누르거나 카드에 포커스를 두고 Enter를 누르면 그 워커의 터미널로 이동한다. 워커 에이전트를 못 찾으면 워크트리의 첫 터미널로 가고 워커 터미널이 아닐 수 있다고 화면 위에 알린다. 에이전트 상태를 못 읽어서 그랬으면 그 이유도 같이 적는다. 터미널로는 못 가고 워크트리만 열었으면 그 이유를 알린다. 카드 아래 "상세"를 펼치면 워커와 체크포인트, 다음 할 일, 브랜치와 경로, 열린 게이트 사유 전문, 그 주문의 최근 이벤트 5개, 작업 내용이 나온다. 작업 내용에는 고친 파일(같은 레포 다른 주문도 고친 파일엔 ⚠), todo 제목과 상태, 서브에이전트 이름과 상태와 경과, 최근 tool 호출 8개, "전체 보기" 버튼이 있다. "전체 보기"를 누르면 워커가 `gestalt conductor browse --no-open --port 0`을 한 번 띄워 두고(워커가 내려가면 같이 끈다) 그 주문의 작업 내용 탭(`#order/<id>/work`)을 브라우저로 연다. 브라우저를 못 여는 화면이면 주소를 알려 준다. todo 막대는 워커가 todo tool로 보고한 것만 그린다. 보고가 아예 없으면 빗금 막대와 "todo 모름"을 그리고 시간으로 퍼센트를 짐작하지 않는다. 작업 내용을 모르는 옛 CLI면 전처럼 체인의 스킬 중 끝난 스킬의 비율을 막대로 그린다. 오르카 워크트리 워커면 그 아래에 에이전트 상태와 맡은 작업, 워커 터미널의 마지막 24줄, "터미널로 이동" 버튼이 붙는다. 워커 에이전트를 못 찾으면 다른 일을 하는 터미널의 출력을 워커 것처럼 보여 주지 않으려고 출력은 안 읽고 그 사실만 적는다. 펼쳐 둔 동안 4초마다 터미널을 다시 읽고 상태가 그대로여도 30초마다 경과 시간을 새로 그린다. 화면이 가려져 있으면 둘 다 쉰다. 주문 제목이나 게이트 사유 같은 바깥 글은 텍스트로만 넣는다. 사이드바에도 같은 이름의 패널이 있다. 에디터와 같은 코드로 그리고 폭이 480px 이하면 세로로 쌓는다. 머리글 한 줄, 컨덕터 요약, 카드 목록, 게이트, 최근 이벤트 8줄, 상태줄 순이다. 지도 패널은 그대로 둔다.
- 게이트 승인과 거절은 버튼을 한 번 더 눌러 확정해야 보낸다. 워커가 `gestalt conductor gate resolve <id> --approve|--reject [--answer] --defer-delivery --json`을 부른다. 오르카 워커에는 결정이 바로 가고 git-worktree와 서브에이전트 워커에는 컨덕터 세션이 다음 tick에 전한다. 오르카 워커에 바로 못 전했을 때도 다음 tick이 다시 전하고 세 번 못 전하면 그만둔다. 컨덕터 세션에도 오르카가 없으면 그 tick에서 그만둔다. 플러그인은 미룬 경우 "다음 tick에 전해요"라고만 알린다. `--defer-delivery`를 모르는 옛 CLI면 플래그 없이 다시 부르고 돌아온 `hostActions`를 "컨덕터 세션에서 처리할 일"로 보여 주기만 한다. 그때는 컨덕터 세션에서 직접 처리해야 결정이 워커에 닿는다.
- 끝난 주문(done, failed, cancelled)은 지울 수 있다. 패널의 주문 줄과 보드의 주문 상세에 지우기 버튼이 붙고 레포 상세와 보드의 레포 카드에는 "끝난 주문 N개 지우기"가 붙는다. 이것도 한 번 더 눌러야 확정되고 워커가 `gestalt conductor order remove <id...> --json`을 부른다. 컨덕터 저장소에서 빠져서 `order show`로도 못 보고 같은 지라 티켓이나 PR로 주문이 다시 생기지 않는다. 워크트리와 브랜치는 그대로 둔다. 열린 게이트가 있거나 워커가 돌거나 멈춘 채 남아 있어 못 지운 주문은 이유와 함께 보여 준다. `order remove` 명령이 없는 CLI에서는 눌러도 CLI 오류만 나온다.
- 오르카 모바일은 플러그인 패널을 못 그린다. 그래서 폰에서는 보기 전용 페이지로 본다. `mobilePort`를 정하면 워커가 이 맥의 `127.0.0.1`에만 그 포트를 연다. 페이지는 확인 대기 게이트를 맨 위에 모은 뒤 레포마다 진행 중인 주문의 위계와 접힌 끝난 주문 묶음을 그린다. 버튼은 없고 승인과 거절, 지우기는 데스크톱에서 한다. 화면이 켜져 있는 동안 10초마다 본문만 다시 받아 오고 펼쳐 둔 칸은 그대로 둔다. 머리글의 "터미널"을 누르면 같은 페이지가 컨덕터 터미널 화면으로 바뀌고 "← 기본 보기"로 돌아온다. 터미널 화면은 에디터와 같은 마크업을 쓰고 폭이 480px 이하면 사이드바처럼 세로로 쌓는다. 카드의 "상세"는 펼칠 수 있지만 컨덕터가 아는 것만 싣는다. 워커 id와 브랜치, 체크포인트의 스킬과 단계는 컨덕터가 정한 값이고 카드 칩과 이벤트 로그에도 이미 나와서 폰 상세에도 싣는다. 워커 터미널과 이동 버튼, 워크트리 경로는 없다. 워커가 직접 쓴 글(다음 할 일, 대기 사유, bypass 내용, 보고 요약)과 계정 이름도 싣지 않는다. 작업 내용은 고친 파일과 지금 파일만 그대로 싣고 todo와 서브에이전트는 개수만 싣는다. 최근 tool 호출은 명령 앞부분이 들어 있어 싣지 않고 "전체 보기" 버튼도 없다. 경로나 토큰이 섞일 수 있어서 대기는 기한만, 이벤트 로그의 보고와 대기, bypass 줄은 시각과 유형, 주문 id만 남긴다.

## 설정

| 키 | 비워 두면 | 언제 적나 |
|---|---|---|
| `gestaltPath` | PATH의 `gestalt` | 오르카가 셸 PATH를 못 물려받아 "gestalt 실행 파일을 못 찾았어요"가 뜰 때 절대 경로를 적는다 |
| `stateDir` | status JSON의 `stateDir` | status JSON에 `stateDir`을 안 싣는 CLI를 쓰면서 저장소를 기본 위치 밖에 뒀을 때만 같은 경로를 적는다 |
| `mobilePort` | 0, 꺼짐 | 폰에서 보기 전용 페이지를 보고 싶을 때 남는 포트(예: 8792)를 적는다 |

status JSON에 `stateDir`과 `workerKind`, `worktreeName`을 안 싣는 CLI는 저장소 경로와 워커 워크트리를 알려 주지 않는다. 그때는 저장소가 기본 위치 밖이면 `stateDir` 설정으로 알려 줘야 하고 주문을 눌러 워크트리로 이동할 수도 없다.

위계는 status JSON의 `parentOrderId`, `parentWorktree`, `baseBranch`로 그린다. 이 필드를 안 싣는 CLI에서는 위계 트리 없이 상태별 목록만 나온다.

머지된 주문 중 지라 키가 있고 유형이 bug, task, sub-bug인 주문은 배포 신호가 올 때까지 `merged`로 남는다. status JSON은 이런 주문에 `awaitingDeploy: true`를 싣고 패널과 보드, 터미널 화면, 폰 페이지는 이 주문을 "머지됨" 대신 "배포 대기"로 그린다. 상태별 목록에서도 머지됨과 따로 묶어 앞에 둔다. status JSON은 `src/conductor/jira.ts`의 `isAwaitingDeploy`로 가르고, 그 안에서 엔진의 머지 뒤 정산과 같은 `waitsForDeploy`를 쓴다. 이 필드를 안 싣는 CLI에서는 전처럼 머지됨으로 나온다.

## 폰에서 보기

`mobilePort`를 8792로 정했다면 테일스케일로 테일넷 안에만 잇는다.

```bash
tailscale serve --bg --https=443 --set-path=/conductor http://127.0.0.1:8792
```

폰에서 `https://<맥 이름>.<테일넷>.ts.net/conductor`를 연다. 테일스케일은 경로 접두사를 떼고 Host 헤더는 그대로 넘긴다. 페이지는 자기 주소로 다시 요청하니 접두사를 몰라도 된다. 터미널 화면은 `https://<맥 이름>.<테일넷>.ts.net/conductor?view=terminal`이다. 경로(`./terminal`) 대신 쿼리로 가르는 건 테일스케일 주소가 슬래시로 끝나지 않아서다. 상대 경로 `./terminal`은 `/terminal`로 풀려 접두사가 떨어진다. `tailscale funnel`로 인터넷에 열지는 않는다. 페이지에 인증이 없어서 테일넷 밖에서는 아무나 주문 제목과 게이트 사유를 읽게 된다.

두 화면 다 같은 규칙을 따른다. 서버는 GET과 HEAD만 받는다. Host가 루프백 주소나 `*.ts.net`이 아니면 403을 돌려준다. 아무 웹사이트가 DNS를 이 맥으로 돌려 페이지를 읽어 가는 일(DNS rebinding)을 막으려는 것이다. 주문 제목과 게이트 사유는 지라나 PR에서 온 글이라 전부 이스케이프해서 그린다. 저장소 경로와 gestalt CLI 오류 원문은 인증 없는 페이지라 싣지 않는다. 터미널 화면은 여기에 더해 워커 터미널 출력과 워커가 직접 쓴 글, 계정 이름도 뺀다. 게이트 사유는 두 화면 다 보여 준다. 폰에서 확인 대기 게이트를 알아보려면 사유가 있어야 하고 테일넷 안에서만 열리는 페이지라서다. 데스크톱 에디터와 패널은 전부 보여 준다.

## 권한

`notifications:show`, `workspace:read`, `workspace:write`, `agent:read`, `terminal:read`, `settings:own`, `storage:own`만 쓴다. 워크스페이스 권한은 워커 워크트리와 그 터미널을 찾아 여는 데만 쓴다. `agent:read`와 `terminal:read`는 터미널 화면에서 카드를 펼쳤을 때 워커 에이전트 상태와 터미널 마지막 줄을 읽는 데만 쓴다. 읽은 출력은 데스크톱 화면에만 그리고 폰 페이지에는 싣지 않는다. 터미널 출력에 토큰이나 경로가 섞일 수 있고 폰 페이지에는 인증이 없어서다. 터미널에 글을 보내거나 에이전트를 띄우는 권한은 받지 않는다.

새로 받은 두 권한도 사람이 승인해야 쓸 수 있다. 승인하기 전에는 상세에 "에이전트 상태를 못 읽었어요"가 뜨고 터미널 출력은 안 나온다. 이동할 때는 워크트리의 첫 터미널을 연다. 이 기능이 없는 옛 오르카에서는 "이 오르카는 … 지원하지 않아요"가 뜬다.

## 개발

```bash
orca plugin validate ./orca-plugin --json
orca plugin test ./orca-plugin --json     # src/*.test.ts(x)
orca plugin check ./orca-plugin --json    # src/panel.check.ts 시나리오, 보드 에디터 점검
cd orca-plugin && npx tsc -p .
```

테스트와 check 시나리오는 진짜 gestalt 대신 `test/fake-gestalt.mjs`를 부른다. `--state-dir`로 받은 폴더의 `fake-status.json`과 `fake-resolve.json`을 그대로 내보내니 실제 컨덕터 저장소는 건드리지 않는다.
