# Gestalt Conductor (Orca 플러그인)

Gestalt 컨덕터가 굴리는 주문과 사람 확인을 기다리는 게이트를 오르카 사이드바와 상태 표시줄, 에디터 탭 보드에 보여 준다. 게이트 승인과 거절도 여기서 한다.

## 하는 일

- 워커가 `gestalt conductor status --all --json`을 불러 읽는다. 이벤트 로그를 직접 재생하지 않으니 저장소 꼴이 바뀌어도 CLI만 맞으면 된다.
- 저장소의 `events.jsonl`을 지켜보다 바뀌면 다시 읽는다. 파일이 없으면 5초마다 생겼는지 보고 그동안 "컨덕터 저장소 없음"을 띄운다.
- 상태 표시줄에 `주문 N · 확인 대기 M`을 띄운다. 확인 대기가 있으면 warning, 저장소가 없거나 CLI가 실패하면 danger이고 이유는 툴팁에 있다. 누르면 다시 읽는다.
- 새 게이트가 열리면 데스크톱 알림을 한 번 띄운다. 알린 게이트 id는 플러그인 저장소에 남겨서 워커가 다시 떠도 또 알리지 않는다.
- 패널은 레포마다 타일 하나를 그린 지도로 시작한다. 타일에는 확인 대기 게이트 수와 상태별 주문 수가 붙고 사람 손이 필요한 레포가 앞에 온다. 타일을 누르면 그 레포의 게이트와 상태별 주문, bypass 사후 보고가 나온다.
- 주문을 맡은 워커의 오르카 워크트리를 찾으면 그 주문을 눌러 워크트리로 바로 이동한다. 패널은 주문 제목이나 위계 트리 항목을 누르면 되고 보드는 노드를 두 번 누르거나 옆의 ↗ 버튼을 누른다. 오르카 플러그인 API는 워크스페이스까지만 열 수 있어서 터미널을 따로 고르지는 않는다. 사이드바에서 워크트리를 누른 것과 같아서 그 워크트리에서 마지막으로 보던 탭이 다시 뜬다.
- 레포 이름 옆에 오르카 프로젝트 이름을 붙인다. 컨덕터는 레포를 `owner/name`으로만 알아서 오르카 `workspace.list`의 `project`로 찾는다. 주문을 맡은 워크트리가 있으면 그 프로젝트를 쓰고 없으면 디렉토리 이름이 레포 이름과 같은 워크스페이스를 본다. 후보가 갈리거나 레포 이름과 같으면 붙이지 않는다. 패널과 보드, 폰 페이지가 다 같다.
- 같은 레포 안에서 하위 주문(`parentOrderId`)이나 부모 워크트리(`parentWorktree`)로 이어진 주문이 있으면 타일에 `하위 N`이 붙고 레포 상세에 위계 트리가 나온다. 하위 주문은 상위 주문 밑에 둔다. 부모 워크트리는 그 워크트리를 맡은 주문이 있으면 그 주문 밑에, 없으면 워크트리 이름과 브랜치를 단 노드 밑에 둔다. 컨덕터가 남긴 관계만 그리고 의존성을 따로 추측하지 않는다.
- 탭 바의 + 메뉴에서 "컨덕터 보드"를 고르면 `.conductor-board` 파일을 여는 넓은 보드가 뜬다. 레포마다 카드 하나에 위계 트리를 그리고 오른쪽에 고른 주문의 상세와 게이트가 나온다. 아무것도 안 골랐으면 열린 게이트 전부가 나온다. 파일 내용은 쓰지도 읽지도 않으니 빈 파일이면 된다.
- 게이트 승인과 거절은 버튼을 한 번 더 눌러 확정해야 보낸다. 워커가 `gestalt conductor gate resolve <id> --approve|--reject [--answer] --defer-delivery --json`을 부른다. 오르카 워커에는 결정이 바로 가고 git-worktree와 서브에이전트 워커에는 컨덕터 세션이 다음 tick에 전한다. 플러그인은 그 경우 "다음 tick에 전해요"라고만 알린다. `--defer-delivery`를 모르는 옛 CLI면 플래그 없이 다시 부르고 돌아온 `hostActions`를 "컨덕터 세션에서 처리할 일"로 보여 주기만 한다. 그때는 컨덕터 세션에서 직접 처리해야 결정이 워커에 닿는다.
- 끝난 주문(done, failed, cancelled)은 지울 수 있다. 패널의 주문 줄과 보드의 주문 상세에 지우기 버튼이 붙고 레포 상세와 보드의 레포 카드에는 "끝난 주문 N개 지우기"가 붙는다. 이것도 한 번 더 눌러야 확정되고 워커가 `gestalt conductor order remove <id...> --json`을 부른다. 컨덕터 저장소에서 빠지고 같은 지라 티켓이나 PR로 주문이 다시 생기지 않는다. 워크트리와 브랜치는 그대로 둔다. 열린 게이트가 있거나 워커가 돌거나 멈춘 채 남아 있어 못 지운 주문은 이유와 함께 보여 준다. `order remove` 명령이 없는 CLI에서는 눌러도 CLI 오류만 나온다.
- 오르카 모바일은 플러그인 패널을 못 그린다. 그래서 폰에서는 보기 전용 페이지로 본다. `mobilePort`를 정하면 워커가 이 맥의 `127.0.0.1`에만 그 포트를 연다. 페이지는 확인 대기 게이트를 맨 위에 모은 뒤 레포마다 진행 중인 주문의 위계와 접힌 끝난 주문 묶음을 그린다. 버튼은 없고 승인과 거절, 지우기는 데스크톱에서 한다. 화면이 켜져 있는 동안 10초마다 본문만 다시 받아 오고 펼쳐 둔 칸은 그대로 둔다.

## 설정

| 키 | 비워 두면 | 언제 적나 |
|---|---|---|
| `gestaltPath` | PATH의 `gestalt` | 오르카가 셸 PATH를 못 물려받아 "gestalt 실행 파일을 못 찾았어요"가 뜰 때 절대 경로를 적는다 |
| `stateDir` | status JSON의 `stateDir` | status JSON에 `stateDir`을 안 싣는 CLI를 쓰면서 저장소를 기본 위치 밖에 뒀을 때만 같은 경로를 적는다 |
| `mobilePort` | 0, 꺼짐 | 폰에서 보기 전용 페이지를 보고 싶을 때 남는 포트(예: 8792)를 적는다 |

status JSON에 `stateDir`과 `workerKind`, `worktreeName`을 안 싣는 CLI는 저장소 경로와 워커 워크트리를 알려 주지 않는다. 그때는 저장소가 기본 위치 밖이면 `stateDir` 설정으로 알려 줘야 하고 주문을 눌러 워크트리로 이동할 수도 없다.

위계는 status JSON의 `parentOrderId`, `parentWorktree`, `baseBranch`로 그린다. 이 필드를 안 싣는 CLI에서는 위계 트리 없이 상태별 목록만 나온다.

## 폰에서 보기

`mobilePort`를 8792로 정했다면 테일스케일로 테일넷 안에만 잇는다.

```bash
tailscale serve --bg --https=443 --set-path=/conductor http://127.0.0.1:8792
```

폰에서 `https://<맥 이름>.<테일넷>.ts.net/conductor`를 연다. 테일스케일은 경로 접두사를 떼고 Host 헤더는 그대로 넘긴다. 페이지는 자기 주소로 다시 요청하니 접두사를 몰라도 된다. `tailscale funnel`로 인터넷에 열지는 않는다. 페이지에 인증이 없어서 테일넷 밖에서는 아무나 주문 제목과 게이트 사유를 읽게 된다.

서버는 GET과 HEAD만 받는다. Host가 루프백 주소나 `*.ts.net`이 아니면 403을 돌려준다. 아무 웹사이트가 DNS를 이 맥으로 돌려 페이지를 읽어 가는 일(DNS rebinding)을 막으려는 것이다. 주문 제목과 게이트 사유는 지라나 PR에서 온 글이라 전부 이스케이프해서 그린다.

## 권한

`notifications:show`, `workspace:read`, `workspace:write`, `settings:own`, `storage:own`만 쓴다. 워크스페이스 권한은 워커 워크트리를 찾아 여는 데만 쓴다. 터미널에 글을 보내거나 에이전트를 띄우는 권한은 받지 않는다.

## 개발

```bash
orca plugin validate ./orca-plugin --json
orca plugin test ./orca-plugin --json     # src/*.test.ts(x)
orca plugin check ./orca-plugin --json    # src/panel.check.ts 시나리오, 보드 에디터 점검
cd orca-plugin && npx tsc -p .
```

테스트와 check 시나리오는 진짜 gestalt 대신 `test/fake-gestalt.mjs`를 부른다. `--state-dir`로 받은 폴더의 `fake-status.json`과 `fake-resolve.json`을 그대로 내보내니 실제 컨덕터 저장소는 건드리지 않는다.
