# 읽기 렌즈 (`/lens`)

논문 PDF나 웹 글, 팟캐스트 하나를 받아 옆에서 같이 읽어 주는 뷰어로 만든다. 슬로건은 "믿을 데와 의심할 데를 같이 짚어주는 읽기"다. 구조를 먼저 보여 주고 모르는 말을 풀어 주며 원문 숫자와 어긋나는 주장을 짚는다.

- 입력은 PDF 파일이나 PDF 주소(arXiv, ACL Anthology 같은), 웹 글 주소, 오디오 파일이나 팟캐스트 피드 주소다.
- 산출물은 `digest.html`(뷰어)과 `digest.md`(마크다운)다. 기본은 뷰어를 로컬 서버로 띄운다.
- 문장마다 원문 출처가 붙는다. 원문 표 숫자와 어긋나는 주장에는 의심 표시가 붙고 본문 끝에 검증 안 된 부분이 모인다.

유튜브 주소나 영상 파일은 [`/video-digest`](./video-digest.md)로 간다. 같은 뷰어와 저장소를 쓰지만 영상 자리에 원문 창이 들어가는 것만 다르다.

## 부르는 법

말로 부른다. 아래 문장이 스킬 `triggers`에 들어 있다.

- "이 논문 같이 읽어줘"
- "이 논문 렌즈로 읽어줘"
- "이 PDF 렌즈로 봐줘"
- "논문 읽기 뷰어 만들어줘"
- "이 글 같이 읽어줘"
- "이 팟캐스트 렌즈로 정리해줘"

PDF 경로나 주소를 같이 주면 된다. Orca 내장 브라우저로 보던 페이지는 주소를 안 줘도 "지금 보는 페이지"라고 부르면 열린다. 로그인해야 보이는 글도 이 길로는 읽힌다. 다만 꺼낸 HTML이 `cache/page.html`에 남아서 개인 정보가 섞였는지 한 번 본다.

슬래시로 부를 때는 `/lens`나 `/gestalt:lens`에 `이름=값`을 붙인다. 전부 선택이다. 단 `source`와 `slug` 중 하나는 있어야 한다. 둘 다 없으면 자료 주소를 묻는다.

| 입력         | 뜻                                                                                                                                                    |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `source`     | PDF 파일이나 주소, 웹 글 주소, 오디오 파일이나 피드 주소. 이미 수집한 slug를 주면 비워도 된다                                                         |
| `kind`       | 자료 종류를 직접 정한다. `pdf`, `web`, `podcast`. 비우면 주소와 확장자로 판단한다                                                                     |
| `slug`       | 저장 폴더 이름. 영문 소문자, 숫자, `-`로 64자까지. 비우면 제목과 주소 해시로 짓는다                                                                   |
| `reportLang` | 리포트를 쓸 언어. 기본은 `ko`다                                                                                                                       |
| `output`     | `viewer`(기본)면 로컬 서버로 띄우고 `md`면 마크다운만 낸다                                                                                            |
| `episode`    | 팟캐스트 피드에서 고를 에피소드 번호. 0이 최신이고 기본이다                                                                                           |
| `depth`      | 바깥 맥락 카드 수. `normal`(기본)은 2장, `deep`은 4장, `none`은 카드를 안 만든다                                                                      |
| `knowledge`  | 이번에만 더 볼 노트 폴더의 절대 경로. 쉼표로 여럿 줄 수 있다                                                                                          |
| `difficulty` | 비우면 보통 리포트가 없을 때만 쓴다. `normal`을 직접 주면 이미 있어도 다시 쓰고, 쉬운 리포트가 있으면 그것도 다시 쓴다. `easy`면 쉬운 리포트를 더한다 |
| `templates`  | 함께 만들 확장 리포트 템플릿 id를 쉼표로 이은 값. `quiz,flashcards` 같은 꼴                                                                           |

종류 판단은 이 순서다. `.pdf` 파일이나 PDF 주소는 논문이다. 오디오 파일이나 피드 주소는 팟캐스트이고 나머지 웹 주소는 웹 글이다. 피드 주소는 경로가 `/feed`, `/rss`, `/feed/atom`, `/feed/podcast` 같은 꼴로 끝나거나 `.rss`, `.xml`로 끝나는 주소다. 호스트가 `feeds.`로 시작하거나 쿼리에 `format=rss`가 있어도 피드다. 주소만으로 애매하면 스킬이 한 번 묻는다.

## 스킬과 CLI의 관계

사람이 CLI를 직접 칠 일은 거의 없다. 스킬이 아래 순서로 명령을 부르고 글을 쓰는 단계만 에이전트에게 맡긴다.

| 단계                | 하는 일                                                                                | 부르는 것                                                                             |
| ------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 수집                | 원문을 문단 단위로 나누고 표와 그림, 쪽 그림을 따로 저장한다                           | `gestalt lens ingest`                                                                 |
| 리포트 작성         | 출처와 의심 표시가 달린 리포트 한 벌을 쓴다                                            | `lens-reader` 에이전트                                                                |
| 합치기와 검사       | 리포트를 `digest.json`에 합치며 표 칸에 붙은 출처와 의심 표시의 숫자를 원문과 대조한다 | `gestalt digest merge`                                                                |
| 바깥 맥락과 내 노트 | 맥락 카드와 연결 카드를 쓰고 붙인다                                                    | `lens-context`, `lens-link` 에이전트, `gestalt lens knowledge`, `gestalt lens attach` |
| 쉬운 리포트와 확장  | 요청했을 때만 더 쓴다                                                                  | `lens-reader`, `video-summarizer` 에이전트, `gestalt digest merge --extension`        |
| 윤문                | 한국어 리포트의 문장을 다듬는다                                                        | `ges_digest`의 `prose_extract`와 `prose_apply`                                        |
| 렌더와 띄우기       | HTML과 마크다운을 코드로 만들고 뷰어를 띄운다                                          | `ges_digest`의 `render`, `gestalt digest serve`, `gestalt digest export`              |

LLM이 도는 곳은 글을 쓰는 단계뿐이다. 수집과 검사, 렌더는 코드가 하고 뷰어 안에서도 LLM을 부르지 않는다. 합치기 검사에서 오류가 하나라도 남으면 저장도 렌더도 되지 않는다. 에이전트가 오류 자리만 고쳐 다시 합치고 세 번을 넘기면 멈춰서 남은 오류를 알려 준다.

이미 수집한 자료는 `slug`만 주면 수집을 건너뛴다. 이미 있는 보통 리포트도 다시 쓰지 않는다.

CLI 서브커맨드 전체는 `gestalt lens --help`와 [mcp-reference.md의 CLI](./mcp-reference.md#cli)에 있다. 직접 쓸 만한 것은 둘이다.

```bash
gestalt digest serve <slug>          # 이미 만든 뷰어를 다시 띄운다
gestalt digest export <slug> --md    # 마크다운만 낸다
```

## 결과물 읽는 법

### 출처 표시와 원문 창

본문 문장마다 출처 칩이 붙는다. 칩을 누르면 원문 창이 그 자리로 움직인다.

| 자료     | 출처 단위         | 원문 창                                                    |
| -------- | ----------------- | ---------------------------------------------------------- |
| 논문     | 쪽과 문단, 표 칸  | 쪽 그림. 칩을 누르면 그 쪽으로 가서 문단을 칠한다          |
| 웹 글    | 문단 번호         | 추출한 문단 목록. 칩을 누르면 그 문단으로 스크롤한다       |
| 팟캐스트 | 문장과 시각, 화자 | 오디오 플레이어와 스크립트. 시각을 누르면 그 자리로 옮긴다 |

팟캐스트는 문장마다 "화자 1", "화자 2"가 붙고 사람 이름은 붙지 않는다.

### 한눈에 보기

도입에 자료 종류마다 정해진 칸이 있다. 칸마다 한두 문장이고 출처가 붙는다. 마지막 `한계` 칸은 원문이 한계를 밝히지 않았어도 비지 않는다. 아래 의심 표시나 한계 단락에서 가장 무거운 것 하나를 옮겨 온다.

| 자료     | 칸                     |
| -------- | ---------------------- |
| 논문     | 문제, 방법, 결과, 한계 |
| 웹 글    | 주장, 근거, 한계       |
| 팟캐스트 | 주제, 주장, 한계       |

### 의심 표시

본문 불릿이 옮긴 주장이 같은 원문의 표나 다른 문단과 어긋날 때 그 문장 바로 아래에 의심 표시가 붙는다. 본문에 펼쳐져 보인다. 종류는 둘이다.

- 숫자 의심은 주장과 표 칸의 숫자가 어긋나거나 같은 설정의 값이 표와 본문에서 서로 다를 때 붙는다.
- 방향 의심은 본문이 "올린다"고 하는데 표의 두 칸은 반대로 움직였을 때 붙는다. 예를 들어 기법을 켰더니 점수가 0.3236에서 0.2862로 떨어진 경우다.

의심 표시에 적힌 숫자는 원문 표 칸의 글자 그대로다. 합치기 검사가 근거에 없는 숫자를 막는다. 차이나 비율을 계산한 값은 들어가지 않는다.

읽을 때 알아 둘 것이 있다.

- 원문 안의 모순만 짚는다. 다른 논문은 다르게 나왔다는 식의 바깥 자료 반론은 맥락 카드에 있다.
- 어긋난 자리가 없으면 의심 표시도 없다. 0개인 리포트가 정상일 수 있다.
- 개선 폭이 작다는 식으로 값의 크기만 평가하는 자리에는 달지 않는다. 그런 자리는 한계 단락에 적힌다.
- 칸 경계를 못 믿는 표(수집 출력의 `주의:` 줄에 나온다)는 방향 의심의 근거로 쓰지 않는다. 근거 문단의 숫자로 숫자 의심을 달거나 달지 않는다.

### 원문 표와 그림

소섹션에 원문 표와 원문에서 잘라낸 그림이 실린다. 표 칸의 글자는 사람이나 에이전트가 옮겨 적지 않고 렌더러가 수집한 `source.json`에서 그대로 옮긴다. 옮겨 적다 틀리는 자리를 없애려는 것이다.

### 인터랙티브 그림

소섹션에 막대를 켜고 끄거나 두 설정을 가로세로로 견주거나 단계를 슬라이더로 넘기는 그림이 붙는 때가 있다. 그림마다 배지가 붙고 배지는 끌 수 없다.

| 구분               | 무엇                                          | 읽는 법                                                                        |
| ------------------ | --------------------------------------------- | ------------------------------------------------------------------------------ |
| A 원문 데이터 그림 | 원문 표 숫자로 만든 그림                      | 값마다 원문 칸을 가리키는 출처가 있고 합치기 검사가 칸 숫자와 대조한다         |
| B 개념 설명 그림   | 원문 개념을 설명용으로 꾸민 작은 예시         | 설명용이라 값과 결과 지표 말이 들어가지 않는다                                 |
| C 원문 그림 재구성 | 원문 그림을 이해한 대로 움직이게 다시 그린 것 | 다르게 그린 점이 적혀 있다. 슬라이더 칸 수는 원문 그림의 장면 수를 넘지 않는다 |

### 바깥 맥락 카드

절 옆에 붙는 카드다. 카드마다 바깥 출처 주소가 달린다. 종류는 넷이다.

| 종류            | 담는 것                                                                                              |
| --------------- | ---------------------------------------------------------------------------------------------------- |
| 연구 계보       | 선행 연구를 연도와 함께 토대, 구성 요소, 비교 대상으로 나누고 이 자료가 가져온 것과 바꾼 것을 적는다 |
| 결과 해석       | 원문 숫자를 그 분야의 바깥 기준에 놓고 본다                                                          |
| 반론            | 다른 연구가 다르게 보고했거나 같은 기법을 먼저 썼거나 방법의 약점을 짚은 자료                        |
| 검증 안 된 부분 | 원문 주장을 확인한 후속 연구나 재현이 있는지 찾아보고 없으면 없다고 적는다                           |

카드 수는 `depth`가 정한다. 카드마다 웹 검색을 두세 번 하므로 `deep`은 그만큼 오래 걸린다. 웹 검색 도구가 없는 환경이면 맥락 카드는 건너뛰고 그 이유가 보고에 적힌다.

### 내 노트 연결 카드

내가 써 둔 노트에서 원문의 이름이나 개념과 겹치는 줄을 찾아 원문과 잇는 카드다. 인용은 노트 글자 그대로여야 합치기 검사를 통과한다. 연결 카드를 쓰는 에이전트는 웹을 못 열고 맥락 카드를 쓰는 에이전트는 파일을 못 읽는다. 페이지에 섞인 지시문이 노트 내용을 밖으로 보낼 길을 막으려고 둘을 나눴다. 설정은 아래 [내 노트 연결](#내-노트-연결)에 있다.

### 한계 단락

본문 끝에 늘 펼쳐져 있는 "검증 안 된 부분"이다. 의심 표시에서 나온 것, 원문이 스스로 밝힌 한계, 원문이 검증하지 않은 주장을 모은다. 맥락 카드에서 나온 한계 줄도 뒤에 붙는다. 줄마다 원문 근거가 달리고 한계 줄에 적힌 숫자도 근거 칸과 대조한다.

### 쉬운 리포트와 확장 리포트

`difficulty=easy`를 주면 보통 리포트를 풀어 쓴 쉬운 리포트가 더해진다. 뼈대와 출처, 의심 표시, 한계 단락은 보통 리포트와 같아서 뷰어의 쉽게 보기 토글로 오가도 같은 자리를 가리킨다. 맥락 카드와 연결 카드도 보통 리포트 것을 그대로 붙인다.

`templates`를 주면 템플릿마다 확장 리포트가 뷰어의 탭으로 붙는다. 템플릿 목록과 각 모양은 [video-digest 문서의 확장 리포트](./video-digest.md#확장-리포트)에 있다. 렌즈에서는 두 가지가 다르다.

- 댓글 분석은 쓸 수 없다. 댓글은 유튜브 영상에만 있다. 못 쓰는 템플릿은 만들지 않고 보고에 적힌다.
- 논문과 웹 글에는 시각이 없어서 타임스탬프나 마인드맵의 출처가 시각 대신 쪽이나 문단 번호로 그려진다.

확장 리포트의 숫자는 합치기 검사가 원문 표와 대조하지 않는다. 의심 표시와 한계 단락처럼 막아 주는 검사가 없으니 숫자를 옮긴 자리는 원문과 한 번 견준다.

### 뷰어 버튼

`serve`로 연 뷰어에서 아직 없는 쉬운 리포트를 고르거나 확장 탭의 "+ 더 만들기"에서 템플릿을 고르면, serve를 띄운 Claude Code 세션으로 요청이 들어가 그 세션이 리포트를 만든다. 만드는 동안 뷰어에 만드는 중 표시가 뜨고 끝나면 새로고침 없이 그 자리에 들어간다. 세션을 못 찾으면 뷰어가 명령을 보여 주니 복사해서 붙여 넣는다. 따로 연 터미널에서 띄운 serve는 늘 복사 쪽으로 간다. 요청이 세션에서 어떻게 다뤄지는지(승인 창이 뜨는지 등)는 아직 사람이 확인해야 한다. 자세한 동작은 [mcp-reference.md의 뷰어 버튼 요청](./mcp-reference.md#뷰어-버튼-요청-post-__request)과 [peer.md의 들어가는 길](./peer.md#들어가는-길)에 있다.

## 내 노트 연결

연결 카드가 찾을 노트 폴더는 세 군데서 합쳐진다. 사용자 설정 `~/.gestalt/lens.json`, 레포의 `gestalt.json`에 적은 `lens.knowledgeSources`(레포 안 경로만), 부를 때 준 `knowledge`다. 처음 쓸 때는 스킬이 노트 폴더 후보(이름이 notes, kb, wiki 꼴인 폴더, Obsidian 보관함, Logseq 그래프, 노션 내보내기 폴더)를 최근에 고친 순서로 최대 세 개 보여 주며 연결할 폴더를 묻는다. "연결 안 함"을 고르면 다음부터 묻지 않는다. 노션 MCP가 세션에 붙어 있으면 "노션에서도 찾기"를 고를 수 있고 이때는 관련 페이지를 최대 다섯 개 받아 쓴다.

```bash
gestalt lens notes list                 # 연결한 폴더와 노션 사용 여부
gestalt lens notes add <폴더>...        # 연결
gestalt lens notes remove <폴더>
gestalt lens notes decline              # 쓰지 않음. 다음부터 묻지 않는다
```

노트 폴더는 읽기만 하고 `.md`, `.markdown`, `.txt`만 본다. 1MB를 넘는 노트는 건너뛰고 파일 수와 후보 줄 수에도 상한이 있다. 상한에 닿았으면 노트를 일부만 훑었다고 보고에 적힌다. 자세한 설정은 [configuration.md의 읽기 렌즈](./configuration.md#읽기-렌즈-lens)에 있다.

## 사전 준비와 막힘

LLM을 부르지 않는 명령이라 이 기능만을 위한 API 키 설정은 없다. 글을 쓰는 단계는 세션의 에이전트가 맡는다.

원문 추출은 파이썬 패키지(pdfplumber, trafilatura, faster-whisper, sherpa-onnx)로 한다. 시스템 파이썬의 pip가 오래된 머신이 있어서 렌즈 전용 가상환경을 권한다.

```bash
python3 -m venv ~/.local/share/gestalt/lens-venv
~/.local/share/gestalt/lens-venv/bin/python -m pip install --upgrade pip
~/.local/share/gestalt/lens-venv/bin/python -m pip install pdfplumber trafilatura faster-whisper sherpa-onnx
```

파이썬은 `GESTALT_LENS_PYTHON`, 위 가상환경, `python3` 순서로 찾는다. 모듈이 없다는 오류가 나면 오류에 실린 설치 명령이 보고에 적히고 멈춘다. 스킬이 설치를 대신 하지는 않는다.

자료별 제약은 이렇다.

| 자료     | 알아 둘 것                                                                                                                                                                                            |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 논문     | 300쪽을 넘으면 읽지 않고 멈춘다. 필요한 쪽만 잘라 낸 PDF로 다시 돌린다. 신뢰할 수 없는 PDF는 컨테이너나 별도 계정 같은 격리 환경에서 돌린다                                                           |
| 논문     | 칸 경계를 못 믿는 표와 원문에서 잘라내지 못한 그림은 수집 출력의 `주의:` 줄과 보고에 나온다                                                                                                           |
| 웹 글    | 로그인해야 보이는 글은 Orca 내장 브라우저로 연 탭에서 부른다. 로컬 HTML 파일도 받으며 이때 `--url`로 원래 주소를 적는다                                                                               |
| 팟캐스트 | faster-whisper(기본 small 모델)로 받아쓰고 sherpa-onnx로 화자를 가른다. CPU에서는 오디오 길이보다 오래 걸릴 수 있다                                                                                   |
| 팟캐스트 | 화자 구분 모델(약 33MB)은 처음 한 번 받아 `~/.local/share/gestalt/lens-models`(`GESTALT_LENS_MODELS`로 바꾼다)에 둔다. 받은 파일의 sha256이 맞지 않으면 모델을 쓰지 않고 화자 없이 시각만 출처로 단다 |
| 팟캐스트 | 화자 구분이 필요 없으면 `gestalt lens ingest`에 `--no-speakers`를 붙인다. 오디오 재생은 `serve`로 열었을 때만 된다                                                                                    |

뷰어의 손글씨 제목 글꼴은 구글 폰트에서 받는다. 열 때 밖으로 나가는 요청을 없애려면 `GESTALT_DIGEST_EXTERNAL_FONTS=0`을 주고 다시 렌더한다. 끄면 제목이 명조로 보인다. 이미 만든 `digest.html`에는 링크가 남아 있다.

## 저장 위치

레포 루트(스킬이 `pwd`로 정한 작업 디렉토리) 아래 `.gestalt/digest/<slug>/`에 저장한다. 영상 요약과 같은 자리이고 `digest.json`의 `source.kind`로 갈린다. `.gestalt/`는 보통 gitignore 대상이라 커밋되지 않는다.

```
transcript.json    문단 단위 원문 (팟캐스트는 받아쓴 문장)
source.json       표 칸과 그림, 쪽 목록
pages/ tables/ figures/   PDF 쪽 그림과 원문에서 잘라낸 표와 그림
knowledge.json    내 노트에서 찾은 연결 후보
digest.json       출처가 달린 리포트 여러 벌
digest.html       뷰어
digest.md         마크다운 (첫 리포트)
cache/            원본 PDF, HTML, 오디오
```

작업 중간에 `report.draft.json`, `cards.draft.json`, `links.draft.json` 같은 초안 파일도 생긴다.

뷰어 주소는 `http://127.0.0.1:<포트>/<slug>/`이고 포트는 기본 7893부터 빈 곳을 쓴다. 같은 PC 밖으로는 안 나간다. 서버는 끝나지 않는 명령이라 스킬이 백그라운드로 띄우고 끄는 법을 알려 준다. 직접 끌 때는 `kill $(lsof -ti tcp:<포트> -sTCP:LISTEN)`을 쓴다.

렌즈 뷰어는 쪽 그림과 잘라낸 표와 그림을 `pages/`, `tables/`, `figures/`에서 상대 경로로 읽는다. 그래서 HTML을 파일 하나로 옮기지 말고 폴더째 들고 다니거나 `serve`로 본다. `file://`로 열어도 원문 창은 동작하지만 팟캐스트 오디오는 `serve`로 열어야 재생된다.

남에게 넘길 HTML이면 공유용이라고 말해 둔다. 원문 쪽 그림과 잘라낸 표와 그림이 빠지고 원문 창에는 추출 텍스트만 남는다. 내 노트 연결 카드도 빠져서 노트 경로와 인용이 남에게 가지 않는다. 옮긴 표 칸과 리포트 본문, 바깥 맥락 카드는 그대로다. 나중에 `serve`를 부르면 잘라낸 그림과 연결 카드가 있는 HTML로 다시 덮인다.
