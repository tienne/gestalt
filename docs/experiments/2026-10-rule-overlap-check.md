작성 2026-10-02. 구현은 `src/humanize/overlap.ts`, 실행은 `pnpm verify:rule-overlap`이다. 리뷰 단계로 넘기는 자리는 `src/harness-review/rule-overlap.ts`다.

## 묻는 것

같은 날 분석한 로컬 PR 리뷰 스레드 336개에서 요구사항 공백(SPEC_GAP)이 25개였다. 그중 10개는 룰북 PR에서 "룰 두 개가 겹치면 어느 쪽이 이기나"였다. 착수 전에 인터뷰로 묻기보다 룰북을 검사해서 리뷰어보다 먼저 꺼낼 수 있는지 본다.

## 설계

### 룰을 읽는 단위

룰은 표의 행에만 있지 않다. 행이 길어지면 상세를 표 아래 문단으로 빼는데 ca3a2dbb의 '원본' 경계가 그 문단에 있었다. 그래서 룰 하나만 부르는 헤딩 아래 문단(`### B-5 대체어`)과 볼드 도입구가 룰을 부르는 문단(`(F-9 오적용 주의)`)을 그 룰에 붙인다. 대체어 표처럼 "쓰지 말 것"과 "이렇게" 칸이 있는 표도 금지와 처방 예시로 읽는다.

따옴표마다 종류를 붙인다. 금지 예시, 처방 예시, 예외 예시, 언급 넷이다. 문장 단위로는 못 가른다. "문서가 정하면 대상이고(`타입을 못 박다`), 사람들이 협의해 정하면 예외다(`팀이 일정을 못 박았다`)"처럼 한 문장이 반대 판정을 같이 들고 있어서다. 그래서 차례대로 본다.

1. 화살표 왼쪽은 금지, 오른쪽은 처방이다. 패턴 칸의 화살표만 반대다(`canonical → "정본"`)
2. 따옴표 바로 뒤 서술어를 본다. `"산출물"은 빠지고 "계측기"는 걸린다`처럼 한 마디 안에서 따옴표마다 판정이 갈린다. 나열한 따옴표는 마지막 따옴표 뒤 서술어를 함께 쓴다
3. 마디(쉼표나 대시로 끊은 구간)의 표지를 본다. 예외 표지, 대상 표지, 처방 표지 순서다
4. 아무 표지도 없으면 패턴 칸에서는 금지 예시로, 처방 칸과 문단에서는 언급으로 본다. "F-8은 물리 '측량' 동사만 보므로" 같은 언급을 금지 예시로 세면 행렬이 소음으로 찬다

예외 문장을 셀 때는 예외를 정의하는 꼴(예외는, 예외다, 대상이 아니다, 에서만 쓴다, 그대로 둔다)만 센다. "예외가 전부 문맥이라 탐지기가 없다"처럼 예외를 말하기만 하는 문장까지 세면 예외 개수가 부풀어 클린 커밋에서도 후보가 뜬다. 고치기 전후 숫자는 아래 클린 커밋 절에 있다.

### 탐지기 행렬 (게이트)

모든 예시를 모든 룰 탐지기에 돌린다. 탐지기는 주입받는다. 과거 커밋을 재현할 때 그 커밋의 탐지기로 돌려야 해서다.

| 코드 | 무엇 | 등급 |
|---|---|---|
| `after-hit` | 처방 예시가 아무 탐지기에나 걸린다. 룰북대로 고친 글이 다시 걸린다 (꼴 2) | error |
| `form-exempt-hit` | "형태로 빠진다"고 적은 예외 예시를 자기 탐지기가 잡는다. 룰북과 탐지기가 같은 사실을 반대로 적었다 | error |
| `exempt-hit-other` | 예외로 둔 말을 다른 룰 탐지기가 잡고 둘 사이 순서를 정한 문장이 없다 (꼴 1) | error, 순서가 있으면 info |
| `exempt-hit-self` | 뜻으로 가르는 예외를 자기 탐지기가 잡는다. F-10처럼 "탐지기는 넓게 걸고 사람이 다시 본다"고 적은 룰이 많다 | info |
| `before-miss` | 금지 예시를 자기 탐지기가 놓친다. 탐지기 범위를 좁혀 적은 룰이 섞여 있다 | info |
| `before-hit-other` | 금지 예시가 다른 룰에도 걸리고 순서 문장이 없다 | info |

탐지기가 없는 룰은 건너뛰지 않고 "판정 불가" 목록으로 내보낸다. 지금 54개다. 이 룰들의 자기 판정(놓침, 자기 예외)은 이 층에서 안 된다. 다른 룰 탐지기에 거는 판정(처방이 다른 룰에 걸리는지)은 그대로 돈다.

`pnpm verify:rule-overlap`이 error만 실패로 친다. `pnpm gate`와 postbuild(CI가 도는 `pnpm build` 뒤)에 넣었다. 지금 룰북에서 error는 0개다. 아래 재현 커밋 18개에서도 0개였다. 그래서 게이트에 걸어도 문제없는 PR이 막히지 않는다고 봤다. 검사를 끄는 플래그는 두지 않았다. 걸린 자리가 맞는 판정이면 룰북 문장을 고치는 게 답이다. 끄는 수단을 밖에 두면 그게 우회로가 된다는 선례가 있다.

### 겹침 후보 (리뷰 단계)

탐지기로 판정이 안 되는 겹침은 문장 꼴로 추려 질문으로 넘긴다. 판정이 아니다.

| 코드 | 무엇 | 겨냥한 꼴 |
|---|---|---|
| `target-exempt-share` | 같은 룰의 금지 예시와 예외 예시가 같은 내용어를 쓴다. 한 문장 안에서 둘을 맞세운 자리는 이미 경계를 그은 것이라 뺀다 | 3, 4 |
| `exceptions-no-order` | 예외 정의가 둘 이상인데 "앞선다", "먼저", "우선"이 없고 그중 하나가 이번에 새로 생겼다 | 3 |
| `cited-no-order` | 다른 룰을 부르며 경계를 긋는데("갈린다", "구별", "경계") 둘에 함께 걸리는 말을 어느 쪽으로 볼지 정한 문장이 어느 룰에도 없다. 두 룰이 함께 가진 문단은 뺀다 | 1, 5 |
| `shared-source` | 서로 안 부르는 두 룰이 같은 영어 원어를 다룬다. 영어 구와 한글 음차를 자음 뼈대로 맞춰 본다(`low-hanging fruit`와 `로우 행잉 프룻`) | 2 |

후보는 이번 변경에서 새로 생긴 문장이 낀 것만 낸다. 비교는 문장 단위다. 행 단위로 하면 긴 행 한 칸을 고쳐도 행 전체가 새것이 된다. 룰북 전체로 돌리면 지금 룰북에서도 후보가 16개 나와서 PR마다 같은 질문이 반복된다.

후보는 `gestalt harness-refs collect`가 `ruleOverlap` kind로 싣는다. harness-reviewer가 이미 "후보는 판정이 아니다"라는 계약으로 읽는 목록이라 새 경로를 안 만들었다. 판정 기준은 `plugin/review-agents/harness-reviewer/AGENT.md`의 `ruleOverlap` 절에 있다. 반대 판정이 나는 입력을 하나 만들어 대지 못하면 결함으로 안 올린다. 탐지기 행렬의 error는 같은 kind에 `needsLlmJudgment: false`로 실린다.

LLM 판정은 따로 안 넣었다. 후보를 읽는 쪽이 harness-reviewer라서 질문을 판단하는 건 이미 모델이 한다. 놓친 사례 넷(아래)은 전부 뜻을 봐야 갈리는데, 이걸 잡으려고 룰북 전체를 모델에 읽히는 단계를 따로 둘지는 사례가 더 쌓이고 정할 일이다.

- 같은 PR 안에서도 라운드마다 head가 다르다. 사례마다 코멘트가 달린 라운드의 head에서 돌렸다. 687ecbb4와 4fd38f6d는 이벤트의 `headSha`가 a3c2beb인데, 그 커밋은 리뷰 게시 3분 전에 올라온 수정본이다. 코멘트가 겨냥한 문장은 그 앞 커밋 3c8f69b에 있어서 3c8f69b로 돌렸다.
- 각 head 커밋의 `src/humanize/`를 꺼내고 지금의 `overlap.ts`만 그 옆에 넣어 그 커밋 탐지기로 돌렸다. 룰북은 head와 PR base 양쪽에서 읽어 바뀐 문장을 셌다.
- 클린 커밋은 사례 PR 넷 밖에서 룰북을 고쳤고 뒤에 겹침 문제가 안 나온 커밋 12개다. GitHub PR(#28)로 들어간 커밋은 리뷰 코멘트가 0개인 것만 골랐다. 클린 커밋은 그 커밋 하나의 diff로 돌렸다.

- `shared-source`의 자음 뼈대는 거칠다. 6자 미만은 우연히 맞아서 뺐다. `silver bullet`과 `실버 불릿`처럼 음차가 자음을 빼먹으면 안 맞는다.
