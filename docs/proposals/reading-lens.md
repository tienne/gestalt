# 읽기 렌즈 (reading lens)

## 배경

### 목표

논문과 PDF, 웹 글, 팟캐스트를 video-digest처럼 문장마다 출처가 달린 뷰어로 읽게 한다. 요약을 한 장 더 만드는 게 목적이 아니다. 그 분야를 아는 사람이 옆에서 같이 읽어 주는 경험을 만든다. 구조를 먼저 보여 주고 모르는 말을 풀어 주고 바깥 맥락을 붙이고 믿기 어려운 자리를 짚고 내가 이미 아는 것과 이어 준다.

참고한 서비스는 영상과 PDF, 웹 페이지를 AI 렌즈로 읽어 준다고 내세우는 요약 서비스다. 2026-10-28에 로그인한 브라우저로 기존 리포트 두 개를 열어 보고 논문 PDF 하나로 딥 리서치 리포트를 새로 만들어 원문과 대조했다.

### 슬로건 후보

| 후보 | 담는 것 |
| --- | --- |
| 흩어진 문장에서 전체를 읽는다 | 게슈탈트 원리와 바로 이어진다 |
| 어떤 글이든, 그 분야를 아는 사람처럼 | 참고 서비스의 슬로건과 가장 가깝다 |
| 믿을 데와 의심할 데를 같이 짚어주는 읽기 | 참고 서비스와 갈리는 지점을 앞에 둔다 |

세 번째를 제안한다. 아래 시험에서 참고 서비스가 가장 약했던 자리가 본문의 의심이었고 gestalt가 이미 출처 검사를 코드로 하고 있어서 그 차이를 이름에서부터 드러내는 게 낫다.

### 가져다 쓸 수 있는 부품

| 부품 | 위치 | 쓰임 |
| --- | --- | --- |
| 리포트 스키마 | src/digest/schema.ts | `lead`, `sections`, `skipped`, `keywords`를 그대로 쓴다 |
| 출처 검사 | src/digest/lint.ts | 커버리지(`SECTION_GAP`)와 출처 범위 검사를 자료 단위만 바꿔 쓴다 |
| 도식 | src/digest/diagram-schema.ts, src/digest/svg.ts | 모델은 구조 JSON만 쓰고 그림은 코드가 그린다 |
| 뷰어와 서버 | src/digest/render-html.ts, src/digest/viewer-js.ts, src/digest/server.ts | 플레이어 자리를 원문 창으로 바꿔 쓴다 |
| 윤문 | src/digest/prose.ts | 본문과 라벨을 나눠 다듬는 흐름을 그대로 쓴다 |

## 참고 서비스 시험 결과

### 시험한 자료

| 자료 | 종류 | 리포트 | 대조한 원문 |
| --- | --- | --- | --- |
| Figma "Design with Code Layers" | 유튜브 영상 8분 | 기존 리포트 | 영상 스크립트 |
| 팀네이버 DAN25 Keynote 01 | 유튜브 영상 27분 | 기존 핵심 리포트(이름을 바꾸기 전 버전) | 영상 스크립트, 보도 기사 |
| FlavorDiffusion (`aclanthology.org/2025.aisd-main.7.pdf`) | 논문 PDF | 딥 리서치 리포트를 새로 만듦 | 논문 본문과 표 1~6 |

FlavorDiffusion 리포트 하나에 543 크레딧이 들었다. 리포트 본문과 외부 리서치 카드 두 장을 합친 값이다. Starter 요금제(월 9,900원, 5천 크레딧)로 한 달에 아홉 편 정도다.

### 잘한 것

- **원문 옮기기는 정확했다.** Code Layers 리포트에서 틀린 문장을 못 찾았고 FlavorDiffusion 리포트의 표 1~6은 숫자가 전부 원문과 같았다.
- **외부 리서치 카드가 날카로웠다.** 카드 네 장 중 둘은 이 논문의 약점을 바로 짚었다. CSP 기법은 이미 FlavorGraph에 있던 것이고 diffusion이 모든 설정에서 이기지 않으며 새로 제안한 재료 조합은 맛으로 검증하지 않았다는 내용이었고 셋 다 원문과 맞았다.
- **출처 칩이 원문 위치를 연다.** 페이지 칩을 누르면 옆 창에 PDF가 그 페이지로 열린다. 리포트 하나에 페이지 출처가 202개 붙어 있었다.
- **처음 보는 말에 '쉽게' 풀이가 붙는다.** 용어 위에 올리면 짧은 설명이 뜬다.
- **원문 커버 배지를 단다.** "원본 100% 커버"를 리포트 머리에 보여 준다. gestalt는 같은 값을 lint에서 계산하지만 뷰어에는 안 보여 준다.

### 못한 것

- **본문은 논문을 그대로 믿었다.** 외부 카드가 짚은 약점이 본문에는 안 들어왔다. 표 4에서 노드 50개 설정은 CSP를 켜면 NMI가 0.3236에서 0.2862로 떨어지는데 본문은 CSP가 성능을 올린다고만 썼다. 표 6의 "창의적 조합" 점수는 0.0003~0.0006이라 거의 0인데 그 단서 없이 새 조합을 발견했다고 소개했다.
- **출처 없는 그림을 지어냈다.** DAN25 리포트의 "신뢰 확보 3요소" 파이 차트는 35%, 35%, 30%로 나뉘어 있는데 영상 어디에도 그 비율이 없다.
- **원문 그림을 재현하는 척했다.** FlavorDiffusion 리포트의 인터랙티브 Figure 1은 HTML을 열어 보니 시드 `12345`로 고정한 의사 난수로 점수를 만들고 단계마다 정답 쪽으로 직선으로 다가가게 짜여 있었다. 화면의 "GT 일치도 14.2%"도 이 난수에서 나온 값이다. 논문 데이터는 하나도 안 쓰였다.
- **AI 생성 이미지에 오타와 없는 설정이 들어갔다.** 일곱 장 중 여러 장에 "규로", "그래표", "그래큐" 같은 글자가 보였고 논문에 없는 노드 500개 설정이 그려진 그림도 있었다.
- **원문 그림 크롭과 캡션이 세 군데 어긋났다.** 다른 그림의 캡션이 붙어 있거나 그림 일부가 잘렸다.
- **연도를 틀렸다.** DAN25 핵심 리포트는 2025년 11월 발표인데 "2024년 여름 통합 에이전트 출시"처럼 이미 지난 연도로 적었다.
- **영상 장면을 시각으로만 골랐다.** 캡처가 슬라이드가 아니라 말하는 사람 얼굴인 경우가 많았다. video-digest 4-4에서 같은 문제를 겪었고 OCR 기반 후보 장면으로 고쳤다.

참고 서비스는 옮기기와 바깥 맥락은 잘하고 의심과 그림에서 약하다. 그림 쪽 결함은 전부 모델이 HTML이나 이미지를 직접 만든 자리에서 났다.

## 천재의 눈

"천재의 눈으로 읽는다"를 동작 다섯 개로 나눴다. 렌즈의 기능 목록은 이 표를 기준으로 삼는다.

| 동작 | 참고 서비스 | gestalt에 있는 것 | 새로 필요한 것 |
| --- | --- | --- | --- |
| 구조부터 본다 | 목차, 핵심 요약 | `lead`의 질문과 답, 대섹션 목차, 도식 | 자료 종류별 한눈에 보기 틀 |
| 모르는 말을 풀어 준다 | '쉽게' 팝오버 | `keywords`의 설명과 첫 출처 | 없음 |
| 바깥 맥락을 안다 | 외부 리서치 카드 | 없음(ges_research는 경쟁사 조사용) | 선행 연구와 반론 카드 |
| 의심한다 | 외부 카드에만 있음 | 없음 | 본문의 주장과 원문 데이터가 어긋난 자리 표시 |
| 내가 아는 것과 잇는다 | 없음 | 코드 그래프, 레포 문서 | 사용자 지식 소스(Bob KB 같은 노트, 레포)와 잇는 카드 |

뒤의 둘이 참고 서비스와 갈리는 자리다. 의심은 접힌 카드가 아니라 본문의 그 문장 옆에 둔다. 연결은 참고 서비스가 사용자 자료를 모르니 애초에 못 하는 일이다. FlavorDiffusion이라면 Bob KB의 향미 노트(`docs/notes/2026-10-28-flavor-ai-opensource-db-papers.md`)에 있는 FlavorGraph 항목과 바로 이을 수 있다.

## 설계

### 전제

- **출처 없는 건 그리지 않는다.** 숫자가 들어간 그림은 원문 표의 칸을 출처로 단다. 원문에 없는 그림은 설명용이라고 화면에 밝히고 원문 그림을 다시 그린 그림은 AI가 이해한 대로 그렸다고 밝힌다. 딱지 없이 원문 그림 자리에 붙는 그림은 받지 않는다.
- **의심은 원문 안에서 찾는다.** 본문 문장의 주장과 같은 원문의 표나 다른 문장이 어긋날 때만 표시한다. 바깥 자료로 하는 반론은 맥락 카드로 따로 둔다. 둘을 섞으면 무엇이 원문 안의 모순이고 무엇이 외부 의견인지 구분이 안 된다.
- **모델은 구조 JSON만 쓴다.** video-digest의 "모델이 쓴 SVG나 HTML 원문을 받지 않는다"(plugin/skills/video-digest/SKILL.md:477)를 그대로 따른다. 인터랙티브 그림도 같다.
- **뷰어는 video-digest 것을 쓴다.** 플레이어 자리에 원문 창을 넣고 출처 칩이 시각 대신 페이지나 문단을 연다. 뷰어를 두 벌 두지 않는다.
- **Passthrough다.** 요약과 맥락 카드, 의심 표시는 Claude Code 세션이 만들어 JSON에 담는다. 뷰어 안에서 LLM을 부르지 않는다.

### 자료별 출처 단위

| 자료 | 출처 단위 | 원문 창 | 새로 필요한 것 |
| --- | --- | --- | --- |
| 논문, PDF | 페이지와 문단 번호, 표 칸 | PDF를 그 페이지로 열고 문단을 칠한다 | 좌표가 붙은 본문 추출, 표 추출, 그림 크롭 |
| 웹 글 | 문단 번호 | 추출한 본문을 그 문단으로 스크롤한다 | 본문 추출(광고와 메뉴 걷어내기) |
| 팟캐스트 | 시각과 화자 | 오디오 플레이어를 그 시각으로 옮긴다 | 화자 구분. 화면이 없어서 프레임 단계는 없다 |
| 유튜브 | 시각 | 지금 그대로 | 없음. video-digest로 넘긴다 |

### 가져올 표현

| 표현 | 참고 서비스에서 본 것 | 렌즈에서 바꾸는 것 |
| --- | --- | --- |
| 바깥 맥락 카드 | 절 옆에 접힌 카드로 붙는다. 연구 계보(연도, 논문, 링크), 선행 연구를 토대와 구성 요소와 비교 대상으로 나눈 라벨, 이 논문이 가져온 것과 바꾼 것, "NMI 0.3410이 이 분야에서 얼마나 좋은가" 같은 결과 해석, 검증 안 된 부분을 담는다 | 칸 구성은 그대로 가져온다. 카드마다 외부 출처 주소를 달고 본문 의심 표시와 구분해 둔다. video-digest의 `background`, `counterpoints` 템플릿은 리포트를 따로 만드는 방식이라 절 옆 카드로 새로 만든다 |
| 원문 표 블록 | 표 번호와 캡션, 쪽 출처를 달고 원문 표를 숫자 그대로 옮긴다 | `table` 블록을 새로 둔다. 칸마다 원문 표 칸을 출처로 단다 |
| 한눈에 보기 | 논문은 핵심, 공백, 접근, 결과 네 칸 표다 | `lead`를 자료 종류별 틀로 늘린다. 논문은 문제, 방법, 결과, 한계 순이다 |
| 질문으로 여는 요약 | 초록을 질문 하나로 바꿔 인용 상자에 담고 맨 위 요약도 질문으로 시작한다 | `lead.question`에 이미 있다. 논문에서는 "이 논문이 풀려는 문제"를 질문으로 쓴다 |
| 장 도입 한 줄 | 장마다 첫머리에 한 줄 요약을 둔다 | 대섹션에 `intro` 한 줄을 더한다 |
| 굵은 주장과 번호 근거 | 절마다 굵은 주장 1~3개를 두고 그 아래 근거에 번호를 단다. 굵은 줄만 훑어도 흐름이 잡힌다 | video-digest 본문 꼴을 그대로 쓴다 |
| 커버리지 배지 | "원본 20구간을 모두 다루었고 202곳을 인용했어요" | lint가 계산한 값을 그대로 보여 주고 건너뛴 구간(`skipped`)을 누르면 목록이 뜬다 |
| 원문 그림 크롭과 원본 토글 | 원문 그림을 잘라 붙이고 "원본" 토글로 원문 쪽과 견준다 | 그림 번호와 쪽으로 위치를 먼저 잡고 자른다. 크롭 옆에 원래 쪽 썸네일을 둬서 캡션이 맞는지 바로 확인하게 한다 |
| 용어 풀이 | 밑줄 친 용어를 누르면 '쉽게' 풀이가 뜬다. 논문에서는 CSP, NMI 같은 전문 용어만 골랐다 | `keywords`에 이미 있다. 풀이에도 원문 첫 등장 위치를 단다 |
| 출처 누르면 원문 위치 | 페이지 칩을 누르면 옆 창이 그 쪽을 연다 | 페이지보다 좁게 문단까지 칠한다 |
| 한계 단락 | 없다. 비판이 접힌 카드에만 있다 | 본문 끝에 "검증 안 된 부분"을 늘 펼쳐 둔다. 의심 표시와 맥락 카드에서 나온 내용을 모은다 |

### 가져오지 않을 것

- AI 이미지 생성 그림. 글자가 깨지고 그림 속 내용에 출처를 달 수 없다.
- 출처 없는 비율 차트. 파이 차트는 원문에 비율이 있을 때만 만든다.
- 모델이 짠 HTML과 스크립트. 인터랙티브 그림은 아래 위젯으로만 만든다.
- 의심을 외부 카드에만 두는 배치. 본문을 읽는 사람이 카드를 안 열면 못 본다.
- 일상어 밑줄. Code Layers 리포트는 "주소", "배달 기능", 조사가 붙은 "캔버스에서"까지 용어로 잡았다. 용어 풀이는 그 분야 사람이 아니면 모를 말에만 단다.

### 인터랙티브 그림

원문에 없는 그림이라도 이해를 돕는다면 넣는다. 대신 그림이 어디서 왔는지에 따라 셋으로 나누고 화면에 다르게 보여 준다.

| 구분 | 무엇 | 화면 표시 |
| --- | --- | --- |
| A. 원문 데이터 그림 | 원문 표의 숫자로 만든 인터랙티브 | 값마다 원문 표 칸 출처 |
| B. 개념 설명 그림 | 원문 개념을 장난감 예시로 보여 주는 그림 | "설명용, 원문 데이터 아님" 배지 |
| C. 원문 그림 재구성 | AI가 원문 그림을 이해한 대로 움직이는 그림으로 다시 그린 것 | "AI가 이해한 대로 다시 그림" 배지, 원문 크롭과 나란히 |

참고 서비스의 Figure 1 인터랙티브가 문제였던 건 원문 그림을 다시 그려서가 아니다. 딱지 없이 원문 그림 자리에 붙였고 원문에 없는 데이터를 난수로 만들었고 원문에 없는 결과 지표까지 달았기 때문이다. 셋 중 어느 구분이든 이 세 가지는 받지 않는다.

**A는 원문 표 숫자만 쓴다.** FlavorDiffusion이라면 표 4의 NMI를 막대로 그리고 CSP 토글을 단다. 토글을 켜면 노드 50개 막대만 내려가서 본문이 놓친 의심 자리가 그림에서 바로 보인다. 표 3의 MSE는 설정과 노드 수 두 축의 열지도로 그린다. 값마다 `{ table, row, col }` 출처를 달고 lint가 추출한 원문 표의 그 칸과 숫자가 같은지 확인한다. 다르면 merge를 막는다.

**B는 원문 데이터를 빌리지 않는다.** diffusion이 노이즈를 걷어내는 과정을 노드 5~6개짜리 장난감 그래프와 단계 슬라이더로 보여 주는 식이다. 조건은 아래와 같다.

- "설명용, 원문 데이터 아님" 배지를 그림 머리에 단다. 렌더러가 붙이고 모델이 끌 수 없다.
- 점수, 정확도, 일치도처럼 결과로 읽히는 지표를 쓰지 않는다. lint가 라벨에서 이런 낱말과 `%`를 찾으면 막는다.
- 원문의 노드 이름이나 재료 이름을 빌려 쓰지 않는다. 빌리면 원문 결과처럼 읽힌다.
- 무엇을 설명하는 그림인지 원문 문장 출처를 하나 단다. video-digest의 `figure` 블록처럼 출처가 없으면 merge를 막는다.

B 그림 제목에 원문 그림 번호("Figure 1", "그림 1")가 들어가면 lint가 막는다. 원문 그림을 다시 그리려면 C로 만든다.

**C는 원문 그림 옆에 AI가 이해한 바를 그린다.** 정적인 원문 그림을 따라가기 어려울 때 쓴다. FlavorDiffusion의 Figure 1이라면 원문은 0단계와 5단계, 10단계 세 장면을 나란히 놓았는데 이걸 단계 슬라이더 하나로 다시 그려서 "단계가 갈수록 엉뚱한 간선이 줄고 정답 간선이 남는다"는 흐름을 손으로 넘겨 보게 하는 식이다. 조건은 아래와 같다.

- 원문 그림 번호를 달고 원문 크롭과 나란히 둔다. 크롭과 재구성을 토글 하나로 바꾸지 않는다. 한쪽만 보이면 어느 게 원문인지 헷갈린다.
- "AI가 이해한 대로 다시 그림" 배지를 렌더러가 붙인다. 모델이 끌 수 없다.
- 숫자는 원문 표나 본문에 있는 것만 쓰고 A와 같은 출처 검사를 받는다. 원문 그림에만 있고 글자로 안 적힌 값은 읽어 내지 않는다. 그 자리는 "많다, 적다", "줄어든다"처럼 숫자 없는 모양으로만 그린다.
- 원문 그림의 장면 수를 넘는 중간 단계를 지어내지 않는다. 원문이 세 장면이면 슬라이더도 세 칸이다. 렌더러는 단계 사이를 보간하지 않는다.
- `differences` 칸에 원문 그림과 다르게 그린 점을 한 줄 이상 적는다. 무엇을 빼고 무엇을 단순하게 했는지다. 비어 있으면 merge를 막는다. 뷰어는 이 줄을 배지 아래에 펼쳐 둔다.
- 원문 그림이 보여 주는 결과를 더 좋게 그리지 않는다. 원문 Figure 1은 10단계에서도 정답과 꽤 다른데 참고 서비스의 그림은 정답으로 깔끔하게 모였다. 이런 차이가 `differences`에 드러나야 하고 이걸 숨기면 의심 표시와 같은 기준으로 잡는다.
- 그림 요소마다 원문 문장이나 원문 그림 출처를 단다.

C는 모델이 원문 그림을 제대로 읽었는지에 달려 있다. 그래서 1차에서는 원문 캡션과 본문 설명만으로 다시 그리고 원문 그림 픽셀을 읽어 값을 뽑는 일은 하지 않는다.

위젯은 미리 정한 종류만 둔다. 모델은 종류를 고르고 데이터 JSON만 채운다.

| 위젯 | 데이터 | 쓰는 때 | 구분 |
| --- | --- | --- | --- |
| 단계 슬라이더 | 단계별 상태 2~10개 | 과정이 단계를 거쳐 바뀌는 개념 | B, C |
| 토글 막대 | 항목별 값과 켜고 끌 조건 하나 | 조건 하나를 켜고 끌 때 결과가 어떻게 바뀌는지 | A, C |
| 열지도 | 두 축 라벨과 칸 값 | 두 설정을 가로세로로 놓고 견줄 때 | A, C |
| 전과 후 | 두 상태 | 바뀌기 전과 뒤 | A, B, C |

video-digest가 도식을 그리는 방식과 같아서 렌더러를 늘리기만 하면 된다. 원문에 섞여 든 지시문이 스크립트로 실행될 길도 없다. 값이 전부 JSON에 적혀 있어서 A와 C의 숫자는 원문 표와 자동으로 대조하고 렌더러가 난수나 보간으로 값을 만들 자리도 없다.

### 진입점

`/lens <주소나 파일>` 스킬 하나로 들어온다. 종류는 아래 순서로 판단한다.

1. 유튜브 주소면 video-digest로 넘긴다.
2. `.pdf` 파일이나 PDF를 돌려주는 주소(arXiv, ACL Anthology 같은)면 논문으로 본다.
3. 오디오 파일이나 팟캐스트 피드 주소면 팟캐스트로 본다.
4. 나머지 웹 주소는 웹 글로 본다.

판단이 애매하면 사용자에게 한 번 묻는다. 뷰어는 `gestalt digest serve`로 띄운다. 브라우저에서 보던 페이지를 바로 렌즈로 여는 방식(Orca 내장 브라우저에서 부르기)은 그다음 단계로 미룬다.

## 단계 나누기

| 차수 | 범위 | 확인할 것 |
| --- | --- | --- |
| 1차 | 논문 PDF. 본문 추출, 표 블록, 그림 크롭, 출처 클릭, 커버리지 배지, 의심 표시, 한계 단락 | FlavorDiffusion으로 만들어 표 4의 CSP 하락을 본문이 짚는지 |
| 2차 | 바깥 맥락 카드와 내 지식 연결 카드 | 같은 논문에서 FlavorGraph 선행 연구와 Bob KB 노트가 이어지는지 |
| 3차 | 인터랙티브 위젯 네 종류와 A, B, C 검사 | 표 4 토글 막대가 원문 숫자와 맞는지, Figure 1 재구성의 `differences`에 10단계에서도 정답과 다르다는 점이 적히는지 |
| 4차 | 웹 글과 팟캐스트 | 본문 추출과 화자 구분 품질 |

## 열린 질문

1. 이름. 스킬 이름은 `lens`, 문서와 화면 이름은 "읽기 렌즈"를 제안한다. 슬로건은 위 표의 세 번째를 제안한다.
2. 저장 위치. `.gestalt/digest/<slug>/`를 같이 쓰면 뷰어와 서버를 그대로 쓰고 `.gestalt/lens/`로 나누면 영상과 읽을거리 목록이 갈린다. 같이 쓰고 `digest.json`에 `source.kind`를 더하는 쪽을 제안한다.
3. PDF 추출 도구. 좌표가 붙은 본문은 `pdftotext -bbox`로 되지만 표는 칸 경계를 못 잡는 논문이 있다. 1차는 FlavorDiffusion과 다른 논문 두세 편으로 표 추출을 먼저 시험해 보고 정한다.
4. 의심 표시가 틀렸을 때. 맞는 주장을 의심으로 잘못 짚으면 렌즈 전체를 못 믿게 된다. 1차는 숫자끼리 어긋난 자리만 표시하고 해석이 갈리는 자리는 맥락 카드로 미루는 쪽을 제안한다.
5. 바깥 맥락 카드 수와 비용. 카드마다 웹 검색을 여러 번 한다. 리포트당 기본 두 장, 깊게 읽기에서 네 장을 제안한다.
6. 내 지식 소스. Bob KB처럼 레포 밖 노트를 어떻게 알려 줄지. `gestalt.json`에 경로 목록을 두는 쪽과 스킬을 부를 때 넘기는 쪽이 있다.
7. 원문 그림 크롭 저장. 논문 그림을 잘라 로컬에 둔다. 개인이 읽는 용도라 문제가 적다고 보지만 리포트를 공유할 때는 크롭을 빼는 옵션이 필요할 수 있다.
8. C 재구성을 모델이 잘못 이해했을 때. 숫자는 원문 표로 대조하지만 "단계가 갈수록 정답 간선이 남는다" 같은 해석은 기계로 못 맞춰 본다. 크롭과 나란히 두는 것과 `differences` 줄로 읽는 사람이 바로 견주게 하는 데서 멈출지, 별도 에이전트에게 원문 그림과 재구성을 같이 보여 주고 어긋남을 찾게 할지 정해야 한다. 1차는 앞쪽을 제안한다.

## 1차에서 정한 것

1차는 인터뷰 없이 진행했다. 범위는 논문 PDF의 본문 추출, 표 블록, 그림 크롭, 출처 클릭, 커버리지 배지, 의심 표시, 한계 단락이다. 열린 질문은 아래처럼 정했다.

- **이름(열린 질문 1).** 제안대로 스킬은 `lens`, 화면 이름은 "읽기 렌즈", 슬로건은 "믿을 데와 의심할 데를 같이 짚어주는 읽기"로 정했다. 리포트를 쓰는 role agent는 `lens-reader`다. CLI는 수집만 `gestalt lens ingest`로 따로 두고 합치기와 렌더, 띄우기는 `gestalt digest` 명령을 그대로 쓴다.
- **저장 위치(열린 질문 2).** 제안대로 `.gestalt/digest/<slug>/`를 같이 쓴다. `digest.json`에 `source.kind`를 두고 merge가 `transcript.json`에서 옮겨 적는다. `transcript.json`의 문장 자리에 PDF 문단이 들어간다. 문단에는 `page`, `role`(`para`, `heading`, `caption`), 캡션이면 `ref`, 원문 창이 칠할 `rects`가 붙는다. 글 자료는 시각이 없어 `startSec`이 0이다. 표와 그림, 쪽 그림 목록은 `source.json`에 따로 둔다. 소섹션 `frameSec`은 선택 칸으로 바꾸고 영상 자료에서 빠지면 lint가 `FRAME_SEC_MISSING`으로 막는다. 데이터 스키마 버전은 1.5.0이다.
- **PDF 추출 도구(열린 질문 3).** 이 머신에 poppler가 없었고 brew도 git 버전 문제로 설치가 안 돼서 `pdftotext -bbox` 대신 pdfplumber(쪽 그림은 pypdfium2)를 썼다. 시스템 파이썬 pip가 오래돼 새 휠을 못 받아서 `~/.local/share/gestalt/lens-venv`에 가상환경을 두고 `GESTALT_LENS_PYTHON`이나 이 가상환경, `python3` 순으로 찾는다. 표는 캡션과 같은 단에서 가장 가까운 가로줄 묶음을 표 자리로 잡고 모든 줄에서 비어 있는 세로 띠를 칸 경계로 본다. 세 편으로 시험했다.

  | 논문 | 표 | 칸을 맞게 읽은 표 |
  | --- | --- | --- |
  | FlavorDiffusion(ACL 워크숍, 8쪽) | 6 | 6. 표 4의 NMI 열 칸이 원문과 같다 |
  | Attention Is All You Need(arXiv, 15쪽) | 4 | 2. 표 2는 칸이 합쳐진 머리줄 때문에 줄이 어긋났다 |
  | ACL 2023 long 1번(21쪽) | 10 | 3. 여러 단 머리줄과 빈칸이 많은 표가 대부분이다 |

  booktabs 꼴의 단순한 결과 표는 잘 읽고 여러 단 머리줄 표는 못 읽는다. 그래서 칸이 하나뿐이거나 빈칸이 30%를 넘는 표는 `grid: "loose"`로 적고 뷰어가 원문 크롭을 앞에 두고 옮긴 칸은 접는다. Attention 표 2처럼 loose로 안 걸리면서 줄이 어긋난 표도 있어서 lens-reader 지침에 loose 표 칸을 근거로 쓰기 전에 캡션과 본문으로 확인하라고 적었다. 쪽과 문단 경계는 세 편 모두 쓸 만했다. 수식이 많은 쪽은 아래첨자 줄을 버리고 수식 조각을 앞 문단에 붙여서 문단 번호가 수식 줄마다 늘지 않게 했다.
- **의심 표시가 틀렸을 때(열린 질문 4).** 제안대로 1차는 숫자끼리 어긋난 자리만 표시한다. 리포트 칸으로는 불릿의 `doubt: { note, evidence }`다. `evidence`는 원문 표 칸 `{ table, row, col }`이나 문단 범위 `{ cite }`다. lint가 세 가지를 본다. 근거 표와 칸이 `source.json`에 있는지(`TABLE_REF_UNKNOWN`, `CELL_REF_OUT_OF_RANGE`), note에 근거 칸의 숫자가 원문 꼴 그대로 있는지(`DOUBT_NOT_NUMERIC`), note의 숫자가 전부 근거 칸이 든 줄과 머리줄, 표 번호, 근거 문단에 있는지(`DOUBT_NUMBER_UNKNOWN`)다. 마지막 검사 때문에 두 칸의 차이나 비율처럼 모델이 계산한 숫자는 쓸 수 없다. 줄 이름의 "50 nodes" 같은 숫자는 같은 줄이라 쓸 수 있다. "거의 0이다"의 0은 대조에서 뺀다.
- **한계 단락.** `limits`는 글 자료와 팟캐스트 리포트에서 필수다(`LIMITS_MISSING`). 한 줄마다 원문 근거나 맥락 카드 id를 단다(`LIMIT_NO_SOURCE`). 카드에서 온 줄이 아니면 숫자를 의심 표시와 같은 기준으로 대조한다.
- **한눈에 보기.** `lead.glance`에 `{ kind, text, cite }`를 둔다. 논문은 problem, method, result, limit 네 칸이 다 있어야 하고 웹 글은 claim, evidence, limit, 팟캐스트는 topic, claim, limit이다(`GLANCE_MISSING`). 장 도입 한 줄은 대섹션 `intro`이고 빠지면 경고만 낸다.
- **원문 표와 그림 블록.** 소섹션에 `tables`와 `figures`로 `source.json`의 id만 적는다. 칸 글자는 렌더러가 `source.json`에서 옮긴다. 모델이 표 숫자를 다시 적지 않으니 옮기다 틀릴 자리가 없다. 칸마다 `data-cell="table-4:2:1"`이 붙고 표 캡션의 쪽 칩이 원문 창의 표 자리를 칠한다. 그림은 크롭 옆에 원래 쪽 썸네일을 두고 그림 자리를 칠해 캡션이 맞는 그림인지 견주게 했다. 참고 서비스에서 캡션이 한 칸씩 밀린 문제를 막으려는 것이다.
- **원문 창.** PDF는 쪽 그림(`pages/p<n>.jpg`, 144dpi)을 세로로 쌓고 "추출 텍스트" 보기와 오간다. 출처 칩이나 쪽 칩을 누르면 원문 창이 그 쪽으로 스크롤하고 문단 사각형을 칠한다. 브라우저 PDF 뷰어를 iframe으로 띄우는 길은 쪽 이동은 되지만 문단을 칠할 수 없고 CSP에 frame-src를 더 열어야 해서 쓰지 않았다. 쪽 그림이 상대 경로라 `file://`로 열어도 원문 창이 동작한다.
- **커버리지 배지.** 대섹션이 덮은 문단 수와 출처 칩 수를 리포트 도입 아래에 보인다. `skipped`가 있으면 그 목록으로 가는 링크를 단다. lint가 대섹션과 `skipped`로 문단 전체를 덮는지 이미 막고 있어서 배지 값은 늘 lint가 확인한 구조에서 나온다.
- **원문 그림 크롭 저장(열린 질문 7).** 크롭과 쪽 그림은 `.gestalt/digest/<slug>/` 아래에만 두고 gitignore 대상이라 커밋에 안 딸려 간다. 공유할 때 크롭을 빼는 옵션은 1차에 넣지 않았다. `inlineFrames`가 쪽 그림을 싣지 않아서 HTML 한 장만 넘기면 크롭과 쪽 그림이 빠진 채로 보인다.
