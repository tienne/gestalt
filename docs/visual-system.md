# Gestalt 컬러 시스템과 시각화 시스템

Gestalt 제품군이 함께 쓰는 색 역할, 시각화 요소, 모션 규칙이다. 코드는 `src/visual-system/`에 있고 문서 사이트는 정적 HTML 한 장으로 뽑는다.

```bash
pnpm visual:docs                 # .gestalt/visual-docs/index.html
pnpm visual:docs --out <경로>     # 다른 자리에 뽑기
```

## 구성

| 파일 | 하는 일 |
|---|---|
| `color-resolver-js.ts` | 테마 해석 로직(ES5 문자열). Node와 정적 HTML이 같은 문자열을 실행한다 |
| `color.ts` | 배경 6개, 강조색 34개, 상태와 계열, 변경 표시. 기본값은 차콜 `#171717`과 시안 `#62D3EA` |
| `contrast.ts` | 역할별 대비 기준과 204개 테마 검사 |
| `catalog.ts` | 시각화 카탈로그 8개 분류 71개 항목(조합 15개 포함) |
| `render.ts`, `render-combo.ts` | 공통 렌더러. 단계가 있는 그림도 마지막 단계를 기본으로 그린다 |
| `product-examples.ts` | Video Digest 도식과 Lens 위젯을 제품 렌더러로 그린 예제 |
| `motion.ts` | 모션 6개 규칙과 시간 토큰 |
| `css.ts`, `runtime.ts` | 공통 CSS와 단계 조작, 테마 적용 런타임 |
| `status.ts` | 컨덕터 주문 상태와 상태 역할 표. 결과 웹 배지와 Orca 패널이 같은 표를 따른다 |
| `inventory.ts` | 조사 항목과 화면 21개의 이행표 |
| `docs-site.ts`, `verify.ts` | 문서 사이트 생성과 전수 검사 |
| `presentation.ts` | 장표 템플릿 10종의 토큰과 역할 연결, 테마 블록 생성. `pnpm presentation:themes`로 템플릿에 다시 쓰고 `--check`로 낡은 파일만 찾는다 |

## 결정 기록

되돌릴 수 있는 결정이라 근거를 같이 남긴다.

- **해석 로직을 문자열 하나로 둔다.** 서버에서 그린 HTML과 브라우저에서 다시 고른 테마의 색이 갈라지지 않게 하려고 Node도 `new Function`으로 같은 문자열을 실행한다.
- **원색 대신 역할 이름만 쓴다.** 제품 CSS는 `--gestalt-color-<역할>`만 읽는다. 대비가 모자란 원색은 배경 반대쪽으로 섞어 기준까지만 올리고 그 전후 값을 `adjustments`에 남긴다.
- **기본 상태는 최종 단계다.** 스크립트가 꺼진 환경과 인쇄에서도 최종 값, 라벨, 출처가 보여야 해서다. 런타임은 단계를 앞으로 되돌려 보여 주는 일만 한다.
- **문서 사이트는 외부 의존 없는 HTML 한 장이다.** 호스팅과 기술 스택이 미정이라 파일만 열면 보이게 했다. 정해지면 `buildDocsSite()` 결과를 그 자리로 옮기면 된다.
- **Digest 도식 CSS는 `src/digest/diagram-css.ts` 하나로 같이 쓴다.** 요약 뷰어는 그대로, 문서 사이트는 `.vs-product ` 범위를 붙여 부른다. 채움 자리는 `--accent-fill`을 읽는다.
- **영상 요약과 읽기 렌즈는 `src/digest/theme-color.ts`의 테마를 같이 쓴다.** 선택기는 자동, 배경, 강조색이다. 자동은 배경 선택만 지워 OS 밝기(밝으면 종이, 어두우면 차콜)를 따르고 고른 강조색은 남긴다. 예전 라이트, 다크 저장값은 처음 열 때 종이와 차콜로 옮긴다. 부트 스크립트가 해석기를 들고 있어 서버 CSP 해시는 상수에서 다시 계산된다.
- **문서 사이트 예제는 모션 다시 보기 버튼으로 다시 돌린다.** 제품의 진입 모션은 스크롤로 화면에 들어올 때 한 번만 돌아서 문서에서는 볼 틈이 없다. 버튼을 누르면 진입 모션을 처음부터 돌리고 단계가 있는 그림은 1단계부터 마지막 단계까지 넘긴다. Video Digest 도식은 `src/digest/diagram-css.ts`의 `diagramMotionCss()`로 요약 뷰어와 같은 시간표를 쓴다. 모션 줄이기 상태에서는 최종 상태를 바로 보여준다.
- **예제는 전부 Gestalt 데이터로 그린다.** 외부 자료의 이미지나 수치를 옮기지 않고 문서 사이트는 예제마다 "Gestalt 예시"를 단다.
- **장표 템플릿은 생성 결과를 커밋한다.** presentation-designer가 템플릿 파일을 그대로 복사해 쓰기 때문이다. 원래 템플릿의 토큰 이름(`--accent`, `--green` 등)은 두고 값만 역할 변수로 바꿨다. 바탕이 바뀌는 카드와 장 안에서는 글자 토큰을 그 바탕의 짝 역할로 다시 잇는다.
- **장표는 기본 테마를 템플릿마다 따로 둔다.** 원래 성격에 가까운 배경과 강조색 쌍을 `<html>` 속성에 적고 사용자가 고른 값은 장표 주소별로 저장해서 한 장표에서 바꾼 테마가 다른 장표로 번지지 않는다.
- **장표 글자 투명도는 1로 고정한다.** 원래 템플릿은 투명도로 위계를 냈는데 테마를 바꾸면 대비 기준을 못 넘었다. 10종을 테마 5쌍으로 열어 대비를 검사했을 때 원본 147건이 0건이 됐다.
- **순차 공개는 클릭으로 하고 PDF는 한 장에 모은다.** 발표 중엔 fragment가 하나씩 나오고 인쇄와 모션 줄이기에서는 전부 최종 상태로 보인다.
- **1차 제품은 기준 커밋과 같은 입력으로 비교해 검증했다.** Presentation, Lens, Video Digest를 실제 렌더러로 다시 뽑아 본문 글자와 연결 속성(data-*, href, aria-*, id), 마크다운이 기준 커밋 결과와 같은지 보고 브라우저에서 204개 테마 글자 대비를 돌렸다. 결과는 `inventory.ts`의 세 화면 `evidence`에 있다. 2차 화면도 같은 방법으로 검증하고 끝난 화면부터 `verified`로 바꾼다.
- **강조 글자는 background와 surface 위에만 둔다.** `--chip`과 `--hl` 바탕 위에서는 테마에 따라 4.5 밑으로 떨어져서 그 자리는 `--card` 바탕이나 본문 글자색을 쓴다. `tests/unit/digest/theme-contrast-css.test.ts`가 렌더 결과 CSS로 검사한다.
- **PRD View도 영상 요약과 같은 테마를 쓴다.** 예전에는 PRD마다 라이트, 다크를 따로 저장했는데 이제 `gestalt-digest-color` 하나를 같이 읽어서 한 번 고른 테마가 요약 뷰어와 PRD에 함께 적용된다. 예전 PRD별 저장값은 옮기지 않고 자동부터 연다. 레일이 좁아서 선택기는 테마 버튼을 누르면 펼쳐지는 팝업에 넣었다.
- **상태 칩은 바탕을 채우지 않고 테두리로 구분한다.** 상태 글자색도 대비가 보장되는 자리는 background와 surface 위뿐이라 옅은 상태색 바탕을 깔면 그래파이트와 소프트 그레이 배경에서 4.35까지 떨어졌다.
- **Research Figma는 흰 배경 테마 한 벌로 고정한다.** Figma에는 CSS 변수가 없고 공유 파일이라 보는 사람의 테마를 따를 수 없다. 그래서 `figmaColors()`가 흰 배경의 역할 값을 hex로 풀어 스크립트에 넣는다. 섹션 바탕은 상태 채움색을 배경에 10%만 섞어서 본문과 메모 글자가 모든 바탕에서 5.8:1을 넘는다.
- **Research HTML의 테마 선택기는 캔버스 도구 막대에 넣는다.** 문서 보기와 캔버스 보기가 같은 막대를 쓰고 있어서 따로 떠 있는 버튼을 하나 더 두지 않았다. 선택기를 선택값에 잇는 스크립트는 `THEME_SWITCH_JS`로 빼서 다른 화면도 같이 쓸 수 있다.
- **Architecture도 같은 테마 저장값을 읽는다.** 예전 `gestalt-architecture-theme` 라이트, 다크 저장값은 PRD처럼 옮기지 않고 자동부터 연다. 선택기는 도구 막대의 테마 버튼 팝업에 넣었다. 팩마다 정한 노드 종류 색과 클라우드, 데이터 저장소 브랜드 색은 식별용이라 그대로 두고 칩 글자는 본문 글자색으로 바꿔 종류 색은 아이콘과 옅은 바탕에만 남겼다.
- **Delta는 모양으로 먼저 구분하고 색은 거든다.** 추가, 삭제, 수정은 원래 점선과 굵기로 나뉘어 있어서 그 표시는 그대로 두고 선 색만 변경 표시 역할(`diff-*-text`)로 바꿨다.
- **Code Graph와 Execute Evolution은 `src/graph-viz/theme.ts`를 같이 쓴다.** 두 화면 모두 서버나 MCP 도구가 HTML 한 장을 그대로 내보내서 공용 테마와 선택기, 역할 값을 꺼내는 함수를 한 모듈에 묶었다. 계열 1번은 강조색이라 노드 종류와 차트 선은 원래 색상에 가까운 계열 2번부터 쓴다. Code Graph 노드는 CSS 클래스로 칠해서 테마를 바꿔도 다시 그리지 않고 캔버스로 그리는 Evolution 차트는 `gestalt-theme` 이벤트를 받아 다시 칠한다.
- **Local PR은 diff2html 색 변수를 역할로 덮는다.** 라이브러리가 밝은 쪽과 어두운 쪽 변수 두 벌을 들고 있어서 둘 다 변경 표시 역할로 잇고 테마를 바꾸면 색 구성 클래스도 같이 바꾼다. GitHub 하이라이트 테마는 토큰 색이 대비 기준을 못 넘어서 빼고 상태 역할을 본문 글자색과 섞어 칠했다. 줄 앞 +, - 기호는 diff 바탕 위에서도 대비가 보장되는 본문 글자색으로 둬서 변경 종류를 색이 아니라 기호 모양으로 먼저 읽는다.
- **Peer 뷰어는 대화 내용 대신 테마 선택만 저장한다.** 뷰어는 대화 내용을 브라우저 저장소에 남기지 않는다는 원칙이 있어서 공용 테마도 배경과 강조색 id만 저장한다. 데몬이 띄울 때마다 포트가 바뀌어 저장한 테마는 데몬이 떠 있는 동안만 이어진다. 새 줄은 접속하자마자 몰려오는 지난 기록이 끝난 뒤에 붙은 것만 짧게 강조하고 읽던 위치는 건드리지 않는다.
- **Conductor 결과 웹은 상태 칩과 선택 표시를 바탕 없이 그린다.** 주문 상태는 다른 화면처럼 테두리와 상태 글자색으로 나누고 고른 주문과 초점이 간 보고는 왼쪽 강조선으로 보인다. 목록 바탕이 표면 역할이라 그 위에 다른 바탕을 깔면 글자 대비가 보장되지 않아서다. 서버 CSP가 nonce 단 스크립트만 받아서 테마 부트와 선택기 스크립트에도 같은 nonce를 단다.
- **Conductor 승인 페이지와 등록 페이지는 이행표에서 범위 밖으로 돌렸다.** 3차에서 두 화면에 테마를 입히고 검증까지 마쳤는데 main이 Touch ID 승인 경로를 지워(a980e3ff) 화면이 없어졌다. 승인은 운영 봇 채팅 문구로 받으니 이행표에는 화면 대신 그 이유만 남긴다.
- **주문 상태 색은 표 하나로 정한다.** `status.ts`의 `ORDER_STATUS_ROLE`이 대기와 취소는 neutral, 진행과 배포 대기는 info, 확인 대기와 에스컬레이션은 warning, 완료와 머지는 success, 실패는 danger로 정한다. Orca 플러그인은 레포 밖 파일을 못 불러와서 같은 표를 복사해 두고 레포 테스트가 둘을 비교한다. Orca Tone에는 info가 없어서 진행 상태는 호스트 accent로 그린다. 상태줄은 톤과 함께 아이콘 모양도 바꿔 색을 못 보는 사람도 상태를 알 수 있다.
- **Orca 보드와 터미널은 바탕을 호스트에, 상태를 Gestalt에 맡긴다.** 바탕과 글자, 선, 버튼은 오르카 테마 변수를 따르고 변수가 없는 폰 웹 페이지에서만 원래 색으로 그린다. 상태색은 `orca-plugin/src/palette.ts`에 옮긴 상태 팔레트를 쓰고 레포 테스트가 `color.ts`와 비교한다. 터미널의 워크트리 종류 계열색은 상태가 아니라서 그대로 둔다. 폰 페이지는 오르카 테마 변수가 없어서 바탕은 기기 설정을 따르고 상태색만 같은 팔레트로 맞춘다.
- **2차 화면이 전부 검증된 뒤에 3차를 연다.** `verify.ts`의 `screenProgressProblems()`가 앞 단계에 검증 안 된 화면이 남았는데 다음 단계 화면을 진행하거나 근거 없이 `verified`로 바꾸면 문제로 올린다. 2차를 끝내면서 10개 화면 52장을 기준 커밋과 다시 비교했는데 본문 글자는 전부 같았다. 모션 줄이기 상태에서 테마를 바꿔 보니 Code Graph는 배치 시뮬레이션과 확대 전환이, Execute Evolution은 차트 진입 애니메이션이, Architecture는 선과 바탕의 색 전환이 그대로 돌고 있었다. 셋 다 끄고 Code Graph는 배치를 미리 계산해 최종 위치부터 그린다.
- **3차까지 남은 19개 화면을 전부 검증해서 끝냈다.** 기준 커밋 db258c90과 같은 합성 주문과 체크포인트로 Orca 터미널 세 경우와 폰 페이지 세 경우를 다시 뽑아 비교했더니 글자와 링크, 데이터 속성, 접근성 속성이 전부 같았다. 바뀐 건 상태 클래스 이름(`b-green`은 `b-run`, `b-yellow`는 `b-gate`)과 완료 주문의 톤이 neutral에서 success로 바뀐 것뿐이다. 이행표의 조사 18개 중 Git Logs와 Jira Tasks, Orcatopia는 범위 밖이라 화면이 없다. 검증한 화면은 근거와 함께 호스트 제약도 적어야 해서 `screenProgressProblems()`가 제약이 빈 `verified`를 문제로 올린다. 화면마다 남은 제약은 이렇다. Orca 사이드바 패널은 Components 톤이 neutral, accent, success, warning, danger 다섯 개라 info가 없다. 폰 페이지는 오르카 테마 변수를 못 받는다. Architecture Delta는 CSP가 인라인 본문을 해시로만 연다.
- **패키지 분리와 배포는 보류한다.** 지금은 레포 안 모듈로만 쓴다.
