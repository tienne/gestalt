# 영상 요약 뷰어 (`/video-digest`)

유튜브 주소나 영상 파일 하나를 받아 문장마다 출처가 달린 요약 뷰어로 만든다. 목차와 플레이어가 붙고 스크립트가 재생 위치를 따라간다. 같은 내용을 마크다운으로도 낸다. 회의록이나 퀴즈, 마인드맵, 댓글 분석 같은 확장 리포트도 템플릿으로 붙일 수 있다.

- 입력은 유튜브 주소나 로컬 영상 파일 경로다.
- 산출물은 `digest.html`(뷰어)과 `digest.md`(마크다운)다. 기본은 뷰어를 로컬 서버로 띄운다.
- 요약 본문의 모든 불릿에 스크립트 문장 번호 출처가 붙는다. 출처가 어긋나면 합치기 검사가 막아서 렌더까지 가지 못한다.

논문 PDF, 웹 글, 팟캐스트는 [`/lens`](./lens.md)로 간다. 영상은 이쪽이다.

## 부르는 법

말로 부른다. 아래 문장이 스킬 `triggers`에 들어 있다.

- "이 영상 요약해줘"
- "유튜브 영상 요약해줘"
- "유튜브 영상 정리해줘"
- "영상 요약 뷰어 만들어줘"
- "이 강의 영상 내용 정리해줘"
- "이 영상으로 퀴즈 만들어줘"
- "영상 회의록 정리해줘"

주소나 파일 경로를 같이 준다. 슬래시로 부를 때는 `/video-digest`나 `/gestalt:video-digest`에 `이름=값`을 붙인다. 전부 선택이다. 단 `source`와 `slug` 중 하나는 있어야 하고 둘 다 없으면 영상 주소를 묻는다.

| 입력         | 뜻                                                                                                            |
| ------------ | ------------------------------------------------------------------------------------------------------------- |
| `source`     | 유튜브 주소나 로컬 영상 파일 경로. 이미 수집한 slug를 주면 비워도 된다                                        |
| `lang`       | 받을 자막의 언어 코드. 비우면 영상 원어 자막을 받는다                                                         |
| `slug`       | 저장 폴더 이름. 영문 소문자, 숫자, `-`로 64자까지이고 첫 글자는 `-`가 아니다. 비우면 제목과 영상 id로 짓는다  |
| `reportLang` | 요약을 쓸 언어. 기본은 `ko`이고 `en`, `ja` 같은 태그도 된다                                                   |
| `output`     | `viewer`(기본)면 로컬 서버로 띄우고 `md`면 마크다운만 낸다                                                    |
| `difficulty` | 다시 만들 난이도. `normal`이나 `easy`를 주면 그 난이도는 이미 있어도 다시 만든다. 비우면 없는 난이도만 만든다 |
| `range`      | 요약할 구간. `1:30-5:00`이나 `90-300`(초) 꼴이고 끝점은 초 단위 정수다. 비우면 영상 전체다                    |
| `prompt`     | 요약에서 더 다뤄 줬으면 하는 것. 2000자까지다                                                                 |
| `translate`  | 스크립트에 `reportLang` 번역을 붙일지. 기본은 true이고 원어가 `reportLang`과 같으면 건너뛴다                  |
| `ocr`        | 화면 글자를 읽어 요약 보조 자료로 넘길지. 기본은 false이고 슬라이드나 화면 시연 영상에 쓴다                   |
| `templates`  | 함께 만들 확장 리포트 템플릿 id를 쉼표로 이은 값. `meeting,quiz` 같은 꼴                                      |

이미 요약한 영상에 구간이나 요청이 다른 리포트를 더할 때도 같은 명령을 쓴다. `slug`를 주면 수집을 건너뛴다. `prompt`가 붙은 호출은 보통과 쉬운 리포트를 둘 다 새로 만든다.

## 스킬과 CLI의 관계

사람이 CLI를 직접 칠 일은 거의 없다. 스킬이 아래 순서로 명령을 부르고 글을 쓰는 단계만 에이전트에게 맡긴다.

| 단계          | 하는 일                                                         | 부르는 것                                                                                 |
| ------------- | --------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 수집          | 자막을 받아 문장 단위 스크립트로 합친다. 자막이 없으면 받아쓴다 | `gestalt digest ingest`                                                                   |
| 화면 글자     | 일정 간격으로 프레임을 뽑아 화면 글자를 읽고 후보 장면을 고른다 | `gestalt digest ocr`, `gestalt digest scenes`                                             |
| 요약 작성     | 보통 리포트를 쓰고 이를 풀어 쓴 쉬운 리포트를 한 벌 더 쓴다     | `video-summarizer` 에이전트                                                               |
| 합치기와 검사 | 리포트를 `digest.json`에 합치며 스키마와 lint를 검사한다        | `gestalt digest merge`                                                                    |
| 확장 리포트   | 템플릿마다 확장 리포트를 쓰고 합친다                            | `gestalt digest templates`, `gestalt digest template`, `gestalt digest merge --extension` |
| 프레임과 번역 | 소섹션마다 프레임을 뽑고 스크립트 번역을 붙인다                 | `gestalt digest frames`, `gestalt digest translate-apply`                                 |
| 윤문          | 요약 문장과 그림 글자를 다듬는다                                | `ges_digest`의 `prose_extract`와 `prose_apply`                                            |
| 렌더와 띄우기 | HTML과 마크다운을 코드로 만들고 뷰어를 띄운다                   | `ges_digest`의 `render`, `gestalt digest serve`, `gestalt digest export`                  |

LLM이 도는 곳은 요약과 번역, 윤문을 맡는 에이전트 단계뿐이다. 렌더와 뷰어는 LLM을 부르지 않는다. 요약 층과 표현 층이 갈라져 있어서 요약을 다시 쓰지 않고 뷰어만 다시 뽑을 수 있다. 합치기에서 오류가 나면 에이전트가 그 자리만 고쳐 다시 합치고 세 번을 넘기면 멈춰서 남은 오류를 알려 준다. lint 오류가 남은 채로는 렌더하지 않는다.

CLI 서브커맨드 전체는 `gestalt digest --help`와 [mcp-reference.md의 CLI](./mcp-reference.md#cli)에 있다. 직접 쓸 만한 것은 둘이다.

```bash
gestalt digest serve <slug>                       # 이미 만든 뷰어를 다시 띄운다
gestalt digest export <slug> --md --report <key>  # 첫 리포트가 아닌 리포트의 마크다운을 낸다
```

## 결과물 읽는 법

### 출처 표시와 목차

요약 본문의 불릿마다 `[n]` 꼴 출처가 붙는다. n은 스크립트의 문장 번호이고 누르면 그 장면으로 이동한다. 구조는 대섹션과 소섹션 두 단이다. 목차가 이 구조를 따라간다.

소섹션마다 프레임 한 장이 붙는다. `ocr`을 켰으면 슬라이드나 앱 화면이 보이는 장면이 720p 프레임으로 따로 실리고 글자가 읽힌다. 사람만 나오는 장면은 실리지 않는다. 프레임을 못 뽑은 소섹션은 자리가 비고 보고에 한 줄씩 나온다.

대섹션에는 도식이 붙는 때가 있다. 단계, 견주기, 시간 흐름, 원인과 결과 같은 구조가 있는 대섹션에 붙고 그림은 렌더러가 구조를 받아 그린다.

### 플레이어와 스크립트 따라가기

뷰어에는 영상 플레이어와 전체 스크립트가 같이 있다. 스크롤을 움직이면 영상이 그 소섹션으로 따라가고 출처 시각을 누르면 영상이 그 시각으로 옮겨 간다. 이 동작은 `serve`로 열었을 때만 된다. `digest.html`을 파일로 바로 열면 유튜브 플레이어가 153 오류로 막힌다. 이때는 영상 자리에 썸네일과 "유튜브에서 열기" 링크가 뜨고 출처 시각은 새 탭 링크로 바뀐다. 로컬 영상 파일도 `serve`로 열어야 재생된다. 원본 파일을 옮겼으면 영상 자리에 안내문만 뜬다.

스크립트 번역은 문장 아래 한 줄로 붙고 뷰어의 "번역" 버튼으로 숨길 수 있다. 번역이 빠진 문장 수는 보고에 나온다.

### 보통 리포트와 쉬운 리포트

보통 리포트와 쉬운 리포트를 늘 함께 만든다. 쉬운 리포트는 스크립트를 따로 요약하지 않고 보통 리포트를 풀어 쓴 것이라 두 리포트의 구조와 출처가 맞는다. 뷰어를 처음 열면 보통 리포트가 보이고 툴바의 쉽게 보기 토글로 쉬운 리포트와 오간다. 구간을 준 호출은 그 구간만 다루는 리포트가 따로 생긴다.

`digest.md`는 첫 리포트의 마크다운이다. 다른 리포트의 마크다운은 위 `export --report`로 낸다. 리포트 키는 `long-normal-ko`나 `long-easy-ko` 꼴이고 구간 리포트에는 `-r90-300`처럼 시작초와 끝초가 붙는다.

### 확장 리포트

`templates`를 주면 템플릿마다 확장 리포트가 뷰어의 탭으로 붙는다. 확장 리포트의 문장에도 스크립트 문장 번호 출처가 붙는다. 이미 만든 요약에 확장만 더할 때는 요약을 다시 쓰지 않는다.

| id              | 이름          | 만드는 것                                                                                                        |
| --------------- | ------------- | ---------------------------------------------------------------------------------------------------------------- |
| `meeting`       | 회의록        | 회의나 토론 영상을 안건, 결정 사항, 미결 사항, 액션 아이템으로 정리한다. 담당자와 기한은 대사에 나온 것만 적는다 |
| `mindmap`       | 마인드맵      | 영상의 주제를 가지로 펼친 마인드맵 한 장. 첫 가지는 3개에서 7개다                                                |
| `visual`        | 그림 해설     | 핵심 개념 4개에서 8개를 골라 개념마다 그림 하나와 짧은 설명을 짝짓는다. 영상 순서가 아니라 개념 순서를 따른다    |
| `timestamps`    | 타임스탬프    | 주제가 바뀌는 자리마다 시각과 제목을 단 목차                                                                     |
| `quotes`        | 중요 인용구   | 자막 문장을 그대로 옮긴 인용 5개에서 10개                                                                        |
| `background`    | 관련 배경지식 | 영상이 설명 없이 쓰고 지나간 개념을 3개에서 6개 골라 풀어 준다                                                   |
| `counterpoints` | 반대 시각     | 영상의 주요 주장마다 나올 법한 반론과 한계를 짚는다                                                              |
| `blog`          | 블로그 글     | 영상 내용을 문단으로 이어지는 블로그 글 한 편으로 다시 쓴다                                                      |
| `interview`     | 인터뷰 Q&A    | 인터뷰나 대담 영상을 실제로 오간 질문과 답으로 정리한다                                                          |
| `resources`     | 언급된 리소스 | 영상에 나온 책, 도구와 서비스, 사람, 자료를 종류별로 모은다                                                      |
| `flashcards`    | 플래시카드    | 앞면 질문과 뒷면 답으로 복습하는 카드 10장에서 30장                                                              |
| `quiz`          | 퀴즈          | 객관식 5문제에서 10문제. 정답은 하나이고 영상 순서를 따른다                                                      |
| `comments`      | 댓글 분석     | 시청자 댓글을 반응별로 묶는다. 유튜브 영상에만 쓴다                                                              |

템플릿 목록은 `gestalt digest templates`로 볼 수 있다. 레포의 `.gestalt/digest/templates/`에 직접 만든 템플릿을 두면 목록에 함께 나온다. 기본 템플릿과 id가 같으면 내 템플릿이 대신 쓰이고 스킬이 그 사실과 파일 경로를 먼저 알려 준다. 목록에 없는 id는 만들지 않고 보고에 "없는 템플릿"으로 적힌다.

댓글 분석은 먼저 댓글을 받는다. `gestalt digest comments`가 유튜브 댓글을 인기순으로 기본 200개(1개에서 1000개까지) 받아 `comments.json`에 둔다. 작성자 이름과 아이디, 프로필은 저장하지 않고 어디에도 옮기지 않는다. 유튜브가 아닌 영상이거나 댓글을 못 받았거나 받은 댓글이 0개면 그 템플릿만 건너뛰고 이유가 보고에 적힌다. 예시로 실리는 댓글은 원문을 그대로 옮긴 것이다. 글자와 숫자로 4자 이상 이어진 부분이 원문과 다르면 합치기가 거절한다.

### 뷰어 버튼

`serve`로 연 뷰어에서 아직 없는 쉬운 리포트를 고르거나 확장 탭의 "+ 더 만들기"에서 템플릿을 고르면, serve를 띄운 Claude Code 세션으로 요청이 들어가 그 세션이 리포트를 만든다. 만드는 동안 뷰어에 만드는 중 표시가 뜨고 끝나면 새로고침 없이 그 자리에 들어간다. 세션을 못 찾으면 뷰어가 명령을 보여 주니 복사해서 붙여 넣는다. 따로 연 터미널에서 띄운 serve는 늘 이쪽으로 간다. 구간 리포트는 `range`가 명령에 붙고 요청문이 붙은 리포트는 명령 대신 같은 요청으로 다시 만들라는 안내만 뜬다. 요청이 세션에서 어떻게 다뤄지는지(승인 창이 뜨는지 등)는 아직 사람이 확인해야 한다. 자세한 동작은 [mcp-reference.md의 뷰어 버튼 요청](./mcp-reference.md#뷰어-버튼-요청-post-__request)과 [peer.md의 들어가는 길](./peer.md#들어가는-길)에 있다.

## 사전 준비와 막힘

LLM을 부르지 않는 명령이라 이 기능만을 위한 API 키 설정은 없다. 글을 쓰는 단계는 세션의 에이전트가 맡는다.

수집(`ingest`)과 프레임 추출은 yt-dlp와 ffmpeg를 부르는 셸 명령이라 두 도구가 설치돼 있어야 한다. 이미 만든 뷰어를 띄우는 `serve`는 두 도구가 필요 없다.

| 상황             | 알아 둘 것                                                                                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 자막이 없는 영상 | faster-whisper로 받아쓴다. 자막이 있어도 받아쓰려면 `gestalt digest ingest --whisper`를 쓴다                                                                 |
| 자동 자막        | 문장 끝 부호가 없어서 길이와 쉼 간격으로 끊긴다. 문장이 지나치게 짧거나 길면 보고에 적힌다                                                                   |
| 유튜브 403       | ingest가 다른 클라이언트(`web_embedded`)로 한 번 더 시도한다. 그래도 실패하면 오류를 그대로 보여 주고 멈춘다. 쿠키나 로그인은 대신 넣지 않는다               |
| `ocr`            | tesseract가 있어야 한다. 없으면 설치를 대신 하지 않고 안내 문구를 보고에 적은 뒤 화면 글자 없이 진행한다                                                     |
| 구간(`range`)    | 구간에 든 문장이 없으면 명령이 실패한다. `1:30.5`처럼 소수가 든 끝점도 거절된다                                                                              |
| 프레임           | 영상을 낮은 화질로 받아 뽑는다. 못 뽑은 시각이 있어도 렌더는 되고 그 소섹션 자리만 빈다                                                                      |
| 장면 프레임      | 720p 영상을 따로 받아 뽑는다. 못 받으면 낮은 화질에서 뽑고 사유가 출력에 남는다. 받은 720p 영상은 `cache/video-720.*`로 남아 영상 한 편마다 용량이 더 쌓인다 |

화면 글자를 읽을 때 간격은 기본 10초다. `gestalt digest ocr`의 `--interval`로 바꾼다. 화면 글자는 요약 보조 자료이고 고유명사와 숫자, 코드를 확인하는 데만 쓴다. 화면에만 있는 내용이 출처 없이 요약에 들어가지는 않는다.

뷰어의 손글씨 제목 글꼴은 구글 폰트에서 받는다. 열 때 밖으로 나가는 요청을 없애려면 `GESTALT_DIGEST_EXTERNAL_FONTS=0`을 주고 다시 렌더한다. 끄면 제목이 명조로 보인다. 이미 만든 `digest.html`에는 링크가 남아 있다. 설정은 [configuration.md의 환경변수](./configuration.md#환경변수-레퍼런스)에 있다.

영상 자막이나 제목, 설명, 댓글, 화면 글자에 무언가를 하라는 문장이 있어도 에이전트는 따르지 않고 요약할 자료로만 읽는다.

## 다른 스킬과의 경계

| 자료나 목적                           | 쓸 것                                                          |
| ------------------------------------- | -------------------------------------------------------------- |
| 유튜브 영상이나 영상 파일을 요약하기  | `/video-digest`                                                |
| 논문 PDF, 웹 글, 팟캐스트를 읽기      | [`/lens`](./lens.md). 팟캐스트 오디오나 피드도 lens가 받는다   |
| 경쟁 서비스 조사 중에 영상을 분석하기 | `/research`                                                    |
| 영상 속 서비스 화면만 모으기          | `/screen-ref`                                                  |
| 발표 자료 만들기                      | `/presentation`. 카툰과 애니메이션도 이 스킬에서 만들지 않는다 |

영상 하나를 깊이 읽고 정리하는 일은 이 스킬이다. 여러 서비스를 견주는 조사 안에서 영상을 쓸 때는 `research`가 영상 시각을 근거로 달아 한 문서로 묶는다.

## 저장 위치

레포 루트(스킬이 `pwd`로 정한 작업 디렉토리) 아래 `.gestalt/digest/<slug>/`에 저장한다. `.gestalt/`는 보통 gitignore 대상이라 커밋되지 않는다.

```
transcript.json   문장 단위 스크립트 (번역이 붙으면 여기에 들어간다)
ocr.json          화면 글자 (ocr을 켰을 때)
scenes.json       소섹션 장면 후보 (화면 글자를 읽었을 때)
comments.json     유튜브 댓글 (댓글 분석을 만들 때)
digest.json       출처가 달린 리포트와 확장 리포트
frames/           소섹션 프레임 JPEG
digest.html       뷰어
digest.md         마크다운 (첫 리포트)
cache/            받아 둔 영상
```

작업 중간에 `report.draft.json`, `report.easy.draft.json`, `ext.<id>.draft.json` 같은 초안 파일도 생긴다. 구간을 줬으면 그 구간 문장만 잘라 둔 `transcript.slice-<시작>-<끝>.json`도 생긴다.

뷰어 주소는 `http://127.0.0.1:<포트>/<slug>/`이고 포트는 기본 7893부터 빈 곳을 쓴다. 같은 PC 밖으로는 안 나간다. 서버는 끝나지 않는 명령이라 스킬이 백그라운드로 띄우고 끄는 법을 알려 준다. 직접 끌 때는 `kill $(lsof -ti tcp:<포트> -sTCP:LISTEN)`을 쓴다.

파일 하나로 들고 다닐 HTML이 필요하면 `gestalt digest render <slug> --inline-frames`로 프레임을 HTML 안에 넣어 렌더한다. 프레임 한 장이 5MB, 합계가 15MB를 넘으면 그 프레임은 빠지고 경고가 나온다. 이때는 `serve`를 부르지 않는다. `serve`는 띄울 때 렌더를 인라인 없이 다시 돌려 `digest.html`을 덮어쓴다.

남이 건넨 digest 폴더를 `serve`로 열 때는 조심한다. 로컬 영상은 `transcript.json`에 적힌 원본 경로의 파일이 같은 PC의 localhost로 열린다. 출처를 모르는 폴더면 열기 전에 `transcript.json`의 `meta.url`이 어느 파일을 가리키는지 본다.
