# 화면 변경 판정

이 문서는 변경이 화면을 바꾸는지 정하는 기준이다. 아래 자리가 모두 이 기준을 쓴다.

- 수정 전 캡처: `execute`가 첫 태스크 직전에, 컨덕터 워커와 `handoff`로 받은 워커가 코드를 고치기 직전에 [`before-screenshot.md`](./before-screenshot.md)를 돈다
- `pr` 직접 호출: 1단계 4번 질문을 붙일지 정하고 5.5단계에서 전후 이미지를 붙인다
- `ship`의 PR 작성: Phase 1과 Phase 3에서 `pr` 1단계 4번 답을 고른다

자리마다 기준을 따로 적지 않고 이 문서로 링크한다. 기준이 갈라지면 같은 브랜치가 수정 전 캡처에선 화면 변경이고 PR에선 아닌 일이 생긴다.

## 언제 판정하나

코드를 고치기 전에 한 번 보고 GitHub 초안 PR 직전에 최종 diff로 다시 본다.

| 차례 | 언제 | 무엇으로 | 결과를 어디에 |
| --- | --- | --- | --- |
| 첫 확인 | 코드를 고치기 전 | 고치려는 파일 목록(계획의 태스크나 주문 설명) | `$shotTmp/manifest.json`. 후보가 있으면 수정 전 화면을 찍는다 |
| 두 번째 확인 | GitHub 초안 PR을 만들기 직전 | `git diff --name-only "$baseRef"...HEAD`로 본 최종 diff | `prIntent.screenshots`와 PR 본문의 스크린샷 자리 |

두 번째 확인은 첫 확인 결과를 베끼지 않는다. 작업하면서 고칠 파일이 늘거나 줄었을 수 있다. 첫 확인에 없던 후보가 새로 생겼는데 수정 전 이미지가 없으면 그 후보는 "확인 필요"로 시작한다.

## 후보 찾기

확장자와 폴더명은 후보를 찾는 단서다. 걸렸다고 바로 화면 변경으로 확정하지 않고 안 걸렸다고 바로 빼지도 않는다.

단서:

- 확장자: `.tsx` `.jsx` `.vue` `.svelte` `.astro` `.html` `.css` `.scss` `.sass` `.less`
- 경로: `components/` `pages/` `app/` `views/` `screens/` `styles/` 아래 파일
- 이미지와 폰트 같은 정적 자산 (`.svg` `.png` `.woff2` 등)

확장자와 상관없이 아래 근거가 diff에 보이면 후보에 넣는다.

| 근거 | 예 |
| --- | --- |
| 화면을 실제로 그리는 코드 | HTML 문자열이나 템플릿을 만드는 `.ts` (`orca-plugin/src/terminal-markup.ts`처럼 마크업 문자열을 돌려주는 함수), 캔버스나 SVG를 그리는 코드 |
| 스타일과 테마 토큰 | CSS-in-JS 객체, 색과 간격 토큰 파일, Tailwind 설정 |
| 화면 문구와 표시 조건 | 사용자에게 보이는 라벨, 안내문, 에러 메시지, 무엇을 보이고 숨길지 가르는 조건 |
| UI가 직접 쓰는 계산과 변환 | 진행률 퍼센트, 날짜와 금액 포맷, 정렬과 그룹 묶기처럼 화면에 그대로 찍히는 값을 만드는 함수 |

계산과 변환 함수는 화면 코드가 그 함수를 실제로 부르는지 확인한 뒤에 넣는다. `grep -rn "<함수 이름>"`이나 코드 그래프의 blast-radius로 호출하는 쪽을 따라가 화면 코드까지 닿는지 본다. 닿지 않으면 후보가 아니다.

아래만 바뀌었으면 화면 변경으로 확정하지 않는다.

- 테스트와 스토리 파일 (`*.test.*`, `*.spec.*`, `*.stories.*`)
- 화면에 안 닿는 내부 데이터와 로직 (저장소 스키마, 로그, 서버 사이 계약)
- 여러 곳이 같이 쓰는 공용 파일인데 이번 변경이 화면 쪽 용도와 관계없는 경우. 공용 유틸을 고쳤다는 사실만으로는 근거가 아니다. 고친 함수가 화면 코드에서 불리는지까지 본다

## 영향받는 화면과 상태 찾기

후보마다 아래를 정한다.

1. **영향받는 화면**: 후보 파일을 쓰는 화면을 호출 관계로 찾는다. 하나의 마크업 함수를 여러 화면이 쓰면 화면마다 따로 본다 (예: 같은 마크업을 에디터 패널과 폰 웹 페이지가 그리면 둘 다)
2. **대표 상태**: 변경이 드러나는 상태를 고른다. 빈 화면이나 초기 상태 하나로 결론을 내리지 않는다
   - 진행률이면 시작, 중간, 완료
   - 표시 조건이면 조건이 참인 상태와 거짓인 상태
   - 목록이면 빈 목록과 항목이 있는 목록, 길어서 넘치는 목록
   - 에러 문구면 그 에러가 나는 상태
3. **비교 조건**: 수정 전과 후를 같은 데이터, 같은 뷰포트, 같은 테마로 찍는다. 셋 중 하나라도 다르면 무엇이 달랐는지 기록한다

상태를 만들 때는 레포에 이미 있는 것부터 쓴다.

- 테스트 fixture와 목 데이터
- 스토리북 스토리, 렌더링 테스트, 마크업을 HTML로 떨어뜨리는 테스트 헬퍼
- 레포에 있는 캡처 스크립트나 미리보기 서버

새 fixture를 만들어야 하면 레포에 커밋하지 않고 `$shotTmp` 아래에 둔다.

## 판정

후보마다 셋 중 하나로 정하고 근거를 함께 남긴다.

| 판정 | `verdict` 값 | 근거로 남길 것 |
| --- | --- | --- |
| 화면 변경 있음 | `changed` | 차이가 보이는 전후 캡처 (또는 수정 후만). 어느 화면의 어느 상태에서 무엇이 달라졌는지 한 줄 |
| 확인한 화면에서 변화 없음 | `unchanged` | 확인한 화면과 상태 목록, 전후를 같은 조건으로 비교했다는 기록 |
| 확인 필요 | `unverified` | 확인하지 못한 범위와 이유 (실행 환경 없음, 주소 모름, 로그인 필요, 전 이미지 없음 등) |

후보가 하나도 없으면 `none`이다. 이때는 판정 표를 만들지 않는다.

지키는 규칙:

- 실행 환경이나 주소, 로그인, 전후 이미지가 모자라서 못 본 화면은 `unverified`다. `unchanged`로 적지 않는다. 못 본 것과 봤는데 같은 것은 다르다
- `unchanged`는 실제로 전후를 비교한 화면과 상태에만 쓴다. 비교하지 않은 다른 화면까지 넓혀 말하지 않는다
- `changed`면 차이가 드러나는 상태의 캡처를 붙인다. 빈 화면 캡처로는 붙이지 않는다
- 사용자가 붙여 달라거나 빼 달라고 했으면 판정보다 그 요청이 먼저다. 붙여 달라면 `none`이어도 붙인다. 빼 달라면 `changed`여도 이미지는 빼되 판정 줄은 본문에 남긴다

여러 후보의 판정이 섞이면 PR 전체 판정은 `changed` > `unverified` > `unchanged` 순으로 앞선 것을 쓴다. 후보별 판정은 본문 표에 그대로 둔다.

## 기록 꼴

판정 결과는 `pr` 스킬 5.5단계의 `$shotTmp/manifest.json`에 남긴다. 첫 확인과 두 번째 확인이 같은 파일을 쓰고 `check`로 구분한다.

```json
{
  "check": "before-pr",
  "baseRef": "<baseRef>",
  "headSha": "<HEAD>",
  "verdict": "changed",
  "candidates": [
    {
      "file": "orca-plugin/src/terminal-markup.ts",
      "evidence": "진행률 막대 HTML 문자열을 만든다",
      "screens": ["에디터 패널", "폰 웹 페이지"],
      "states": ["시작 0%", "중간 50%", "완료 100%"],
      "verdict": "changed",
      "note": "중간 상태에서 막대 색이 바뀜"
    }
  ],
  "pairs": [
    {
      "label": "패널-중간",
      "url": "http://localhost:3000/panel",
      "state": "중간 50%",
      "viewport": "1280x800",
      "theme": "dark",
      "before": "<절대 경로>/패널-중간-before.png"
    },
    {
      "label": "마크업-완료",
      "url": "file://<절대 경로>/마크업-완료.html",
      "render": "<HTML을 만든 명령>",
      "state": "완료 100%",
      "viewport": "1280x800",
      "theme": "dark",
      "before": "<절대 경로>/마크업-완료-before.png"
    }
  ],
  "unverified": [
    { "screen": "폰 웹 페이지", "reason": "모바일 서버를 못 띄움" }
  ]
}
```

- 위 예시는 두 번째 확인을 마친 꼴이다. 첫 확인(`before-edit`)은 아직 수정 후가 없으므로 전체와 후보별 `verdict`, `note`를 비워 둔다.
- `file://` 쌍은 `render`에 HTML을 만든 명령을 적는다. 수정 후 화면은 그 명령을 고친 코드로 다시 돌려 만든다.
- `candidates`가 비었으면 `"verdict": "none"`과 `reason` 한 줄만 둔다.
- 첫 확인에서 못 찍은 이유는 예전처럼 `skipped`에도 적는다. `pr` 1단계가 이 값을 읽어 한 줄 보인다.
- 두 번째 확인은 `check`를 `before-pr`로 바꾸고 `candidates`와 `verdict`를 최종 diff 기준으로 다시 쓴다. `pairs`의 `before`는 지우지 않는다.

## PR 본문에 싣는 꼴

`pr` 스킬은 판정이 `none`이 아니면 스크린샷 자리에 판정 표를 먼저 두고 그 아래 전후 이미지 표를 둔다.

```markdown
**화면 변경 판정: 화면 변경 있음**

| 후보 | 화면과 상태 | 판정 | 근거 |
| --- | --- | --- | --- |
| `orca-plugin/src/terminal-markup.ts` | 에디터 패널 / 시작, 중간, 완료 | 화면 변경 있음 | 중간 상태에서 막대 색이 바뀜 |
| `orca-plugin/src/terminal-markup.ts` | 폰 웹 페이지 | 확인 필요 | 모바일 서버를 못 띄움 |
```

`unverified`가 하나라도 있으면 확인하지 못한 범위를 표에 그대로 둔다. 그래야 리뷰어가 어디를 직접 봐야 하는지 안다.
