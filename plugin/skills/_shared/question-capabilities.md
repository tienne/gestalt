# 질문 capability와 폴백

스킬의 `AskUserQuestion`은 질문의 의도를 나타내는 Claude Code 표기다. 도구 이름만 바꾸지 말고 아래 순서로 현재 호스트에 맞춘다. 이 문서는 질문을 전달하는 방법만 정하며 워크플로의 기존 필수 답변과 승인 경계를 늘리거나 없애지 않는다. 이미 받은 유효한 답이나 승인을 다시 요구하지 않는다.

## 호출 전 확인

1. 현재 제공된 도구 목록과 실제 입력 스키마를 읽는다. 질문 도구의 **존재**와 **현재 모드에서 호출 가능함**은 별개다. Plan 전용 도구가 목록에 노출돼도 Default 모드에서 쓸 수 있다고 추정하지 않는다.
2. 시스템과 개발자 지침의 목적 제한도 확인한다. 예를 들어 `request_user_input`이 선택적 확인 질문에만 허용되거나 승인 용도로 금지돼 있으면 그 제한을 따른다. 필수 답변이나 승인은 일반 대화로 받는다. 질문 도구를 쓰려고 임의로 mode switch하지 않는다.
3. 질문 개수, 선택지 개수, 단일/다중 선택, 자유 입력, 동기/비동기 여부를 확인한다. `multiSelect`, `options`, `header`, `id` 같은 필드는 실제 스키마가 받을 때만 보낸다. 지원하지 않는 인자는 만들지 않는다.

## 스키마에 맞춰 의미 보존

| 필요한 질문 | 현재 도구의 capability | 전달 방법 |
|---|---|---|
| 하나 고르기 | 단일 선택 지원 | 상호 배타적인 선택지를 실제 스키마로 전달한다. 선택지 수 제한을 지키며 필수 선택지를 임의로 버리지 않는다. |
| 여러 항목 고르기 | 다중 선택 지원 | 실제 다중 선택 필드를 사용한다. 한 번에 묻는 질문 수 제한을 지킨다. |
| 여러 항목 고르기 | 단일 선택만 지원 | 항목별 예/아니오 질문으로 나눠 각 항목의 선택 여부를 보존한다. 질문 수 제한에 따라 여러 번 묻는다. 일반 대화로 `1,3` 같은 번호 조합을 받아도 된다. |
| 자유 답변 또는 선택지 제한 초과 | 스키마로 의미 보존 불가 | 일반 대화로 원문과 필요한 선택지를 보여주고 답을 받는다. 필수 자유 답변을 임의의 추천 선택지로 바꾸지 않는다. |
| 어떤 질문이든 | 도구 없음, 모드 제한 또는 용도 금지 | 일반 대화로 묻는다. 도구 실패를 답변으로 취급하지 않는다. |

예를 들어 `request_user_input`의 실제 스키마가 `questions: [{header, id, question, options: [{label, description}]}]`이고 단일 선택만 지원하면 Claude의 `multiSelect: true`를 복사하지 않는다. 그 도구가 질문 1~3개와 질문당 선택지 2~3개를 요구하면 항목별 예/아니오 질문도 그 개수 안에서 구성한다. `request_user_input_async`가 `questions: [{title, options?: string[]}]`를 받는 환경에서는 그 구조로 옮긴다. 이 예시는 스키마를 읽는 방법을 보여주며 특정 이름이나 버전의 도구가 항상 존재하거나 호출 가능하다는 뜻이 아니다. 자유 입력 UI가 자동 제공되면 별도의 `Other` 선택지를 중복 추가하지 않는 등 해당 도구 지침도 따른다.

## 제출과 응답 대기

- UI의 기본 선택, 추천 표시, 사전 선택은 실제 제출이나 승인이 아니다. 사용자가 보낸 답과 선택만 반영한다. 단순한 시간 경과도 동의가 아니다.
- 비동기 질문 도구가 있으면 반환 직후 답을 받았다고 가정하지 않는다. 기다리는 동안 답에 의존하지 않는 독립 작업만 계속한다. 필수 답변과 승인이 필요한 종속 작업은 실제 응답이 올 때까지 멈춘다. 동기 도구의 빈 결과나 취소도 응답 확정으로 취급하지 않는다.
- **선택적 질문(optional)**에 답이 없으면, 상위 지침과 해당 워크플로가 가정을 허용하고 필수 요구사항이나 승인 경계에 영향을 주지 않으며 합리적인 기본값으로 되돌릴 수 있는 작업만 진행할 수 있다. 답할 기회를 준 뒤 적용한 가정을 명시하고 무응답을 사용자의 선택으로 기록하지 않는다.
- **필수 답변(required) 또는 승인**이 없으면 가정으로 채우지 않는다. 필요한 답이 무엇인지 일반 대화로 알리고 종속 작업을 멈춘다. 승인 용도로 질문 도구 사용이 금지된 환경에서는 일반 대화로 명시적인 승인을 받는다. 허용된 독립 작업이 없으면 답을 기다리며 턴을 끝낸다.

기본 선택된 `전체`를 제출 없이 실행하거나, 인터뷰 무응답을 임의의 요구사항으로 `respond`하거나, 취소를 승인으로 기록하지 않는다. 사용자의 실제 답이 모호하면 그 답에 의존하는 작업 전에 필요한 부분만 확인한다.
