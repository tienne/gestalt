# 리서치 결과물 양식

research 스킬이 내는 결과물의 순서와 섹션별 규칙을 정합니다. 단계 스킬(market-scan, screen-ref, ux-research, reverse-plan)은 이 양식에서 자기 섹션을 채웁니다. research는 섹션을 이어 붙인 뒤 판단과 검증 제안, 열린 질문으로 마무리합니다.

기준으로 삼은 결과물은 Figma "✨ AI로 디자인해보기" 파일의 "서비스 C에서 외식 상품권 이미지와 정보를 가져와서 시안용 DB를 만들어줘" 페이지(node `4:635`)입니다. 다른 팀원이 만든 스킬이 프롬프트 한 번으로 낸 결과를 거꾸로 분석해 뽑았습니다. 원본 스킬을 받으면 이 문서를 거기에 맞춰 고칩니다. 아래 예시 문장은 전부 그 페이지에서 가져왔습니다.

## 전체 순서

| 순서 | 섹션 | 채우는 곳 |
|---|---|---|
| 0 | 전제 | research |
| 1 | 레퍼런스 선정 | market-scan |
| 2 | 시안 | 시안 생성 단계 (범위는 아래 2절 참고) |
| 3 | 비교표 | research |
| 4 | 와우 포인트와 페인 포인트 | ux-research |
| 5 | 레퍼런스가 그렇게 한 이유 | reverse-plan |
| 6 | 판단 | research |
| 7 | 검증 제안 | research |
| 8 | 열린 질문 | research. interview 입력으로 넘깁니다 |
| 9 | 영상 분석 (선택) | research. 영상을 본문에 합칠 때만 붙입니다 |

## 관찰과 해석 나누기

결과물 전체에 걸리는 규칙입니다. evidence-checker가 이 규칙으로 검사합니다.

- **관찰**은 화면에서 보이는 것과 숫자입니다. 표시를 붙이지 않는 대신 출처(캡처 경로나 URL)를 댈 수 있어야 합니다.
- **해석**은 추론, 효과 예측, 레퍼런스의 의도 추정입니다. 문장 끝에 `(해석)`을 붙입니다.
- 아직 정해지지 않은 정책에 기대는 주장은 조건을 괄호에 함께 적습니다. 예: `(한도 정책 확정 뒤, 해석)`
- 섹션 머리말에 근거의 한계를 한 문장으로 밝힙니다. 예: "전환 데이터가 없어 시안 화면과 레퍼런스 리서치를 근거로 한 해석이다."

"늘어난다", "줄어든다", "~할 수 있다", "~해서 ~했다"처럼 효과나 의도를 말하는 문장에 `(해석)`이 없으면 걸립니다.

## 0. 전제

리서치를 시작하기 전에 받아야 하는 입력입니다. **목표 지표가 없으면 research를 시작하지 않고 먼저 묻습니다.** 비교 기준이 전부 목표에서 나오기 때문입니다.

| 항목 | 예 |
|---|---|
| 목표 지표 | 앱 안 구매 건수와 거래액 |
| 규모 가정 | 브랜드는 10개 이상으로 늘어날 예정 |
| 구조 제약 | 상세에 금액 선택이 없다. 금액마다 상품이 따로인 기획서 구조 |
| 아직 안 온 입력 | 브랜드 목록은 서윤님이 공유 예정 |
| 근거의 한계 | 전환 데이터가 없다 |
| 기호 범례 | ◎ 강함, ○ 보통, △ 약함 |

## 1. 레퍼런스 선정

경쟁사를 나열하지 않고 **같은 문제를 서로 다르게 푼 유형**을 고릅니다. 업종이 달라도 됩니다. 3~5개를 고릅니다. 한 유형에 두 곳을 묶어도 됩니다.

이름은 `<기호>. <레퍼런스> 기준: <유형명>` 꼴로 붙입니다.

```text
A. 서비스 A 기준: 순위 리스트와 브랜드 목록형
B. 서비스 B 기준: 혜택 가격형
C. 서비스 C, 서비스 D 기준: 일반 커머스 틀형
D. 서비스 E 기준: 탐색 확장형
```

원본에는 레퍼런스를 왜 골랐는지가 없습니다. 이 양식에서는 유형마다 "어떤 해법을 대표해서 골랐는지"를 한 줄씩 붙입니다.

## 2. 시안

레퍼런스 하나당 시안 하나를 만듭니다. **화면 범위는 모든 시안에 똑같이 맞춥니다.** 범위가 다르면 3절의 비교표가 성립하지 않습니다. 원본은 모든 시안을 홈 첫 화면, 홈 전체 스크롤, 상세 전체 스크롤로 맞췄고 브랜드 페이지는 시안 A에만 있습니다.

시안마다 화면별로 두 목록을 붙입니다.

- **가져온 것**: 레퍼런스에서 빌린 구성
- **보완한 점**: 레퍼런스의 약점을 고친 곳

```text
상세에서 서비스 A에서 가져온 것
- 금액 선택 없이 상품 하나, 브랜드명 링크, 유효기간 행
- 접힌 아코디언
보완한 점: 취소와 환불은 펼침(서비스 A의 접힌 유의사항 약점)
```

시안에는 실데이터를 넣습니다(catalog-collect). 원본은 서비스 C의 실제 가격을 넣어서 할인율이 1~2%밖에 안 된다는 게 드러났습니다. 이 사실이 6절 판단과 8절 열린 질문까지 이어졌습니다. 가짜 숫자를 넣었으면 놓쳤을 부분입니다.

> research가 시안까지 그릴지는 아직 정하지 않았습니다. 시안 없이 끝나는 경우 3절 비교표의 열은 시안 대신 레퍼런스 화면이 됩니다.

## 3. 비교표

행은 기준, 열은 시안입니다.

**기준은 0절의 목표 지표에서 거꾸로 뽑습니다.** 원본은 구매 전환을 목표로 두고 사용자가 지나는 순서대로 기준을 세웠습니다.

| 구간 | 기준 |
|---|---|
| 노출 | 홈 첫 화면에 보이는 상품 수, 목록에서 혜택 노출 |
| 탐색 | 브랜드 10개 이상에서 원하는 걸 찾기 |
| 상세 | 상세 상단 정보, 금액이 다른 상품으로 가는 길, 상세 하단 이어보기 |
| 구매 | 구매 버튼까지 단계, 수량과 객단가 |
| 비용 | 구현 부담과 확장성 |
| 위험 | 남은 위험과 미확정 |

칸 하나는 기호와 근거 한 문장으로 씁니다. 근거는 숫자나 위치 같은 관찰로 댑니다.

```text
△ 3개. 인기 TOP 3 다음에 브랜드 목록이 와서 전체 상품 그리드는 스크롤해야 보임
◎ 6개. 촘촘한 1열 행이라 가장 많음
```

- 구현 부담 행은 기호 대신 정도와 필요한 것을 씁니다. 예: "중간. 순위 산정 기준과 브랜드 로고 이미지가 필요"
- 위험 행은 기호 없이 남은 위험만 씁니다. 해석이 섞이면 `(해석)`을 붙입니다.

## 4. 와우 포인트와 페인 포인트

시안마다 2×2 칸을 채웁니다.

| | 와우 포인트 | 페인 포인트 |
|---|---|---|
| 사용자 관점 | | |
| 비즈니스 관점 | | |

섹션 머리말에 관점을 정의합니다.

- 사용자 관점: 원하는 걸 빨리 찾는지, 구매까지 빠른지, 상품권 비교가 쉬운지
- 비즈니스 관점: 구매 전환, 이탈, 더 많이 팔 수 있는지

칸마다 불릿 2개를 해요체로 씁니다. 비즈니스 관점 칸은 거의 다 효과 예측이라 대부분 `(해석)`이 붙습니다.

```text
비즈니스 관점 / 와우 포인트
• 상세 최하단 다른 상품권이 떠나려던 사용자를 다른 상품으로 돌려요. 서비스 C의 와우 포인트예요 (해석)
비즈니스 관점 / 페인 포인트
• 최하단까지 내려오는 사용자가 적으면 이어보기 효과가 작아요 (해석)
```

## 5. 레퍼런스가 그렇게 한 이유

역기획에서 제일 중요한 섹션입니다. 화면 구성을 뽑는 데서 멈추지 않습니다. 레퍼런스의 본업에서 그 화면이 나온 이유를 찾은 뒤 우리 과제에 맞는지까지 씁니다. 레퍼런스마다 아래 순서를 따릅니다.

1. 본업이나 제품 방향. 서비스가 어떻게 돈을 버는지(수익 모델)도 여기에 적습니다
2. 그래서 이런 화면을 만들었다
3. 우리 과제와 다른 점
4. 가져올 것과 안 가져올 것

```text
서비스 E는 여러 판매자의 상품을 모아 보여주는 게 본업이라 필터와 비교 탐색을 먼저 보여 준다.
우리는 브랜드 10개 이상이라 브랜드 전체 버튼 같은 탐색은 일부 맞고,
판매자를 거르는 필터까지는 필요 없다 (해석)
```

이 섹션은 전부 해석입니다. 원본은 비교표 11번째 행에 넣었는데, 이 양식에서는 reverse-plan이 채우도록 섹션으로 뺍니다.

## 6. 판단

시안 하나를 고르지 않아도 됩니다. 화면 영역별로 결론을 냅니다. 시안끼리 섞는 조합을 제안할 수 있습니다. 섹션 제목에 `(해석)`을 붙입니다.

영역마다 결론 한 줄과 근거 문단을 씁니다. 결론 한 줄은 얼마나 확정됐는지가 드러나게 씁니다.

| 확정 정도 | 결론 줄 예 |
|---|---|
| 유력 | 홈은 C의 리스트 틀이나 D의 칩과 브랜드 전체 버튼 조합이 유력하다 |
| 시험 | 상세 최하단 이어보기는 이탈을 구매로 되돌릴 후보라 다른 안에도 붙여 본다 |
| 보류 | 수량 영역은 한도 정책이 확정된 뒤에 정한다 |
| 제외 | 선물 분기는 이번 과제 범위에서 뺀다. 구매 단계를 하나 늘리기 때문이다 |

보류할 때는 무엇이 정해지면 결정할 수 있는지를 함께 씁니다. 제외는 원본의 "그 외" 칸이 하던 일로, 범위에서 뺀 것과 그 이유를 적습니다.

## 7. 검증 제안

가설마다 세 가지를 씁니다.

- 가설: "X하면 Y가 늘어난다"와 비교할 시안
- 볼 지표: 0절의 목표 지표에서 고릅니다
- 나눠 볼 조건

```text
가설 1. 목록의 할인율을 크게 보이면 상세 진입이 늘어난다 (B 대 A, C, D)
목록에서 상세 진입률과 지면별 구매 건수를 본다. 할인 폭이 작은 상품과 큰 상품을 나눠 본다.
```

아직 의미가 없는 지표는 조건을 붙여 둡니다. 예: "건당 구매 금액은 수량 한도가 확정된 뒤에 의미가 있다."

## 8. 열린 질문

받는 사람(예: PM)을 제목에 적습니다. 머리말에는 이 섹션이 무엇인지 밝힙니다. 예: "시안과 비교 작업에서 근거가 없어 임시로 둔 것들이다. 답에 따라 시안이 바뀌는 곳을 함께 적었다."

항목마다 세 가지를 씁니다.

1. 질문
2. 지금은 어떻게 임시로 뒀는지
3. 답에 따라 바뀌는 시안이나 화면

```text
3. 실제 할인 폭
목업은 서비스 C의 가격(1~2%)이다. 실제 할인 폭에 따라 시안 B처럼 할인율을 크게 강조할 가치가 달라진다.
```

이 섹션은 interview에 그대로 넘길 수 있는 모양이어야 합니다. 3번 항목(답에 따라 바뀌는 곳)이 빠진 질문은 우선순위를 매길 수 없어서 걸립니다.

## 9. 영상 분석 (선택)

영상을 본문에 합칠 때만 8번 뒤에 붙입니다. 영상이 주된 자료이면 본문 대신 영상 분석 문서(`video-analysis`)를 따로 만듭니다. 그 문서는 0번 전제, 1번 레퍼런스 선정, "2. 영상 분석"만 씁니다. 두 모양의 차이와 오가는 방법은 `design.md`의 8.5절에 있습니다.

표는 영상 목록 하나와 묶음별 표로 이뤄집니다. 묶음 순서는 제품별 흐름, 구좌별, 유형별, 종합이고 발견이 없는 묶음은 건너뜁니다.

- 영상 목록: 제품, 영상 제목과 주소, 종류, 출처(공개 영상이나 직접 녹화), 길이.
- 묶음별 표: 영상, 주제, 내용, 근거, 프레임.
- 내용 앞에 방향성이나 관례, 상시나 분기나 단독을 `[방향성] [상시]`처럼 붙입니다.
- 근거 칸에는 관찰, 회사 발언, 해석 중 하나와 영상 시각을 `관찰 (영상 12.5초)`로 적습니다. 관찰과 회사 발언은 시각이 꼭 있어야 합니다.
- 프레임 칸에는 1번 섹션 캡처의 이름을 적습니다. 이미지는 1번에만 실립니다.

```text
제품별 흐름 | 홈에서 상품권까지 | 홈 두 번째 구좌에서 상품권 목록으로 들어간다. | 관찰 (영상 12.5초) | 홈 구좌 진입
```

## 문체

- 섹션 본문은 평서체(~다)로 씁니다.
- 와우 포인트와 페인 포인트 불릿은 해요체로 씁니다.
- 기호(◎○△)는 비교표에서만 씁니다.

## 원본과 다르게 가져가는 점

| 원본 | 이 양식 | 이유 |
|---|---|---|
| 레퍼런스 선정 이유 없음 | 유형마다 한 줄 추가 | 왜 이 레퍼런스인지 읽는 사람이 확인할 수 없어서 |
| 관찰에 출처 연결 없음 | 캡처 경로나 URL을 댈 수 있어야 함 | evidence-checker가 관찰을 검사할 근거가 필요해서 |
| "이유"가 비교표의 한 행 | 별도 섹션 | reverse-plan이 단독으로 채우고 단독으로 쓰일 수 있게 |

## 평가

같은 과제(외식 상품권, 구매 전환 목표)로 research를 돌려 원본 페이지와 나란히 놓고 봅니다.

- 비교 기준이 목표 지표에서 나왔는가
- 효과나 의도를 말하는 문장에 `(해석)`이 빠진 곳은 없는가
- 레퍼런스가 서로 다른 해법 유형인가
- 5절이 본업에서 출발해 우리 과제 적합까지 이어지는가
- 열린 질문마다 답에 따라 바뀌는 곳이 적혀 있는가
