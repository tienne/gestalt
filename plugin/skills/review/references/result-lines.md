첫 줄 링크는 `prTarget`마다 이렇게 씁니다.

| `prTarget` | 첫 줄 |
| --- | --- |
| `github` | 게시 준비 절의 `gh pr view`가 받은 `url` 그대로 |
| `local` | `로컬 PR <id> — gestalt pr show <id>` |
| `none` | 줄을 뺍니다. 브랜치나 커밋을 리뷰해서 가리킬 PR이 없습니다 |

대화가 길어지면 앞 메시지는 압축돼 안 보이고 사용자는 마지막 보고에서 바로 PR로 넘어가서 첫 줄에 둡니다. 링크를 owner와 번호로 손수 조립하지 않습니다. GitHub Enterprise면 호스트가 달라서요. 게시 준비 절의 `gh pr view` 결과에서 `url`을 씁니다. 대상 판별 2번으로 확정됐으면 판별 5번 조회를 안 거쳐서 그 조회의 `url`이 없을 수 있습니다. 게시 준비 전에 멈췄으면 판별 5번 조회의 `url`을 쓰고 그것도 없으면 `gh pr view <번호> --json url --jq .url`로 한 번 받습니다.

게시 의사를 어떻게 판정했는지 한 줄을 남깁니다. 묻지 않고 올렸을 때 사용자가 왜 안 물었는지 알 수 있어야 해서요. 게시를 거절했어도 남깁니다. 리포트 끝의 게시 결과 줄이 있으면 그 바로 아래에 둡니다.

```
**게시 의사**: 있음 — 호출 문장의 "<사용자가 쓴 말>"을 보고 묻지 않고 올렸어요
**게시 의사**: 없음 — 리뷰만 맡기셔서 미리보기 끝에 여쭸어요
**게시 의사**: 없음 — <부른 스킬>이 불러서 미리보기 끝에 여쭸어요
```

있음이면 사용자가 쓴 말을 그대로 옮깁니다. 묻지 않고 올린 근거를 사용자가 바로 확인할 수 있어야 해서요. 의사는 있었는데 어투 검사나 로컬 PR의 `junior` 확인, 연관 PR 알림, 승인 이벤트 때문에 물었으면 있음 줄 끝에 `(<물은 자리>는 따로 여쭸어요)`를 붙입니다. `junior` 확인은 플래그나 사용자 말로 준 값이 1.05단계나 `게시 준비`에서 받은 확인입니다. 프로필에서 온 `junior`는 묻지 않고 내렸으니 넣지 않습니다.

**GitHub PR에 `COMMENT`나 `REQUEST_CHANGES`를 남기고 끝났으면 맨 끝에 한 줄 제안합니다.** 작성자가 대응한 뒤 다시 보는 일을 사람이 기억해서 챙기지 않아도 되게 하려는 것입니다.

```
작성자 대응을 지켜보다 재리뷰할까요? (review-loop)
```

묻기만 합니다. 사용자가 그러자고 하면 그때 `review-loop`를 부릅니다. 이 스킬이 대기나 재리뷰를 직접 걸지 않습니다. `review-loop`는 방금 남긴 리뷰를 이어받아 작성자 대응부터 봅니다. 같은 head를 처음부터 다시 리뷰하지 않습니다. 아래 자리에서는 이 줄을 뺍니다.

- `prTarget`이 `github`이 아닐 때. `review-loop`는 GitHub PR만 따라갑니다.
- 실제로 나간 이벤트가 `APPROVE`이거나 게시를 거절했을 때. 지켜볼 대응이 없습니다.
- 본인 PR이라 `COMMENT`로 폴백했을 때. `review-loop`는 본인 PR이면 멈춥니다. 내 PR을 밀어 올리는 쪽은 `ship`입니다.
- 다른 스킬이 이 스킬을 불렀을 때(review-loop, ship). 부른 쪽이 다음 단계를 정합니다.
